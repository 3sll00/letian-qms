## 1. 探查结论（实测证据）

### 1.1 ERP（管家婆财贸双全，SQL Server）—— 无炉号来源，排除

| 探查项 | 结果 |
|--------|------|
| 含 `Blockno`（批号）列的表 | 50+ 张；有数据的主要是 `DlyOther`(22,774 行)、`DlyCheck`(1,899/23,758)、`DlyBuy`(1,106)、`GoodsStocks`(381) |
| `Blockno` 实际值形态 | `LDW220309-03`、`SKW220310-03`、`00001` —— 前缀+日期+序号的**内部批号**，非钢厂炉号 |
| `DlyNdxCheck`/`DlyCheck` 其他候选列 | `UserDefined01~12` 存 `"00004"` 类字典编码；`Comment` 存"采购订单：JD-…"备注；均无炉号 |
| 全库列名检索（heat/furnace/lu/smelt） | 仅 `Value`/`Column` 等误命中，**不存在炉号字段** |

**判定：ERP 没有任何炉号载体，「按 inbound_no/批次号回填」路径不可行。**

### 1.2 MES（MySQL `mes_letian_test`）—— 唯一真实炉号源

| 探查项 | 结果 |
|--------|------|
| `t_production_task.heat_number` / `steel_mill` | **3,082 / 27,214 行（11.3%）有真炉号**：`24B509530`、`625110039`、`3026632F` 等，钢厂：湘钢/中天/永钢/南钢/沙钢/马钢/兴澄 |
| `batch_no` | 全空（27,214 行 0 填充），不可作键 |
| 炉号分布的工艺路线 | 集中在 `V1.0`(2,875)、`V2.0`(124)、`V1.0车铣`(55)、`V3.0`(27) 主产线；`L1.0`/`C1.0` 等路线全为 0 |
| 炉号→物料 | 1:N —— 单炉号最多跨 8 种物料编码、212 张任务。**禁止按"炉号→物料"反推**，必须任务级关联 |
| `t_check_report` → `task_id` join | 4,915 条检验单中 711 条可达带炉号任务；集中在**检测入库★(707)**、**力学检验★(3)** 工序 |
| `erp_bill_no/head_id/body_id` | **27,214 行全空**，MES→ERP 单据回指不可用 |
| `parent_task_id` 谱系 | **仅 1 行有值**，任务级父子谱系实际未启用，回溯路径不成立 |
| 领料/入库明细表 | `t_picking_detail`、`t_product_warehouse_detail`、`t_purchase_warehouse_detail` 均 **0 行空表** |

### 1.3 QMS 侧既有写路径（已就位，无需新建）

- `inspection_orders.furnace_heat_batch_no` + `furnace_heat_batch_no_norm`（GENERATED 归一化列：trim/大写/去空格-连字符-下划线）+ `heat_source_type`/`heat_source_order_no`（docs/47）
- 表头 PATCH `UpdateInspectionHeaderRequestSchema.furnaceHeatNo` 已可写；写入时**服务端重新解析** `heat_source_type`，请求体不接受客户端自称溯源来源
- MES 同步建单 `mes-sync-service.ts` 已携带 `furnaceHeatNo: rep.heat_number`、`workOrderNo: rep.task_bill_no` —— 同步链路本身已通

## 2. 分检验类型的取数口径

| 检验单类型 | 口径 | 关联键 | 备注 |
|------------|------|--------|------|
| **IQC（来料检验）** | **手工录入**（检验员按钢厂质保书 MTC 填写） | — | ERP 无炉号字段，MES 生产任务覆盖不到来料环节，物理上只有 MTC 是真源。录入端已有 PATCH 写路径 |
| **IPQC_FN（成品检：检测入库/力学检验）** | **MES 回填** | `inspection_orders.work_order_no` ↔ `t_production_task.bill_no`（PT 号）→ `heat_number`/`steel_mill` | MES 炉号 97% 集中在该工序，覆盖率最好；同步新建单已自动带值 |
| **IPQC_CT/IPQC_RL（下料/滚丝）** | **待客户确认**（§4） | 同上 join 成立但对应任务 `heat_number` 为空 | 冷镦/搓丝工序任务在 MES 不带炉号（实测 0 覆盖） |
| **OQC_HEAT / OQC_MACH / OQC_SF（委外）** | **上游带出** | `HeatBatchTraceService`：委外热处理单 → IQC 来料单（docs/47 L1→L2） | 炉号随上游已填值带出；写入时服务端重解析 `heat_source_type` |
| **OQC_SH（出货成品检）** | **上游带出 + 手工兜底** | 同上服务；无带出时手工填 | 出货证书须呈现炉号（EN 10204 3.1 追溯要求） |

## 3. 字段级映射与写入规范

| MES 源字段 | QMS 目标 | 规则 |
|------------|----------|------|
| `t_production_task.heat_number` | `inspection_orders.furnace_heat_batch_no` | **原值写入**；`_norm` 归一化列由 GENERATED 表达式自动生成，不得手写 |
| `t_production_task.steel_mill` | 无独立列 | 不落入 `furnace_heat_batch_no`；如需留存，由写入侧记入 `inspection_notes` 或证书字段袋 `cert_fields`（另议，不在本口径范围） |
| `t_production_task.bill_no` | `work_order_no`（关联键，不重复存） | 建单时已写；回填以此为 join 键 |
| —（服务端解析） | `heat_source_type` / `heat_source_order_no` | 仅表示 docs/47 的**上游带出分类**（`OUTSOURCE_HEAT_TREATMENT`/`IQC_RAW_MATERIAL`/`NONE`），由服务端在写入时解析；**不是**"数据来自 MES/手工"的渠道标记，MES 回填不写此列 |

### 3.1 写入路径约束

- 回填走**与 PATCH 同一应用层路径**（或等价的仓储写入 + 源解析），保证 `heat_source_type` 口径一致；禁止裸 SQL 直接 UPDATE `furnace_heat_batch_no` 跳过带出解析
- 炉号跨物料 1:N（§1.2）：join 必须按任务行（`work_order_no`）而非按物料编码，否则同炉号多规格会错绑

### 3.2 存量回填范围（生产库首次启用时）

- `work_order_no` 非空且能在 `t_production_task.bill_no` 命中的 IPQC 单 → 回填 `heat_number`
- 未命中或命中但 `heat_number` 为空的 → 保持空，由录入界面按 §2 口径兜底
- IQC/OQC 单不参与自动回填（无可靠键）

## 4. ⚠️ 待客户确认（唯一阻塞点）

**冷镦（下料）/搓丝（滚丝）工序的检验单炉号从哪来？**

实测事实：MES 中这两类工序对应的生产任务 `heat_number` 填充率为 0——炉号只在"检测入库/力学检验"任务上登记。

| 方案 | 做法 | 风险 |
|------|------|------|
| A. 近邻继承 | 按「同物料编码 + 最近完工的带炉号任务」回填 | 同一物料短期内可能切换炉号 → **跨炉号误绑**，证书出错法律责任大，**不推荐** |
| B. 手工录入 | 下料/滚丝录入页要求检验员按流转卡/质保书手填（与 IQC 同口径） | 无技术风险；增加检验员一个必填动作 |
| C. MES 侧补数 | 要求 MES 在下料/搓丝任务上也登记 `heat_number`（或开放领料单表） | 最真实但依赖 MES 厂商配合排期 |

**建议口径：短期 B（录入端必填校验），中期推动 C。客户确认后即可进入第 3 步实施。**
