> **版本**：v2.6.0  
> **技术栈**：React 18 / TypeScript 5.6 / Vite 5 / Ant Design 5 / TailwindCSS / ECharts 5 / Lucide React  
> **设计基准**：严格遵循 21 张 WPS 高保真原型图规范，工业级蓝灰质感与极简制造交互

## 2. 设计规范与企业主题定制 (Design Tokens)

系统全局采用制造行业信赖感强的科技深蓝为主色调，符合工业质检现场清晰、高对比度的视觉要求：
- **主品牌色 (Primary)**：`#1677ff`（操作按钮、激活态、高亮指示）
- **合格成功色 (Success)**：`#52c41a`（检验合格、放行标记、流转完成）
- **不合格告警色 (Error)**：`#ff4d4f`（检验不合格、入库阻断、严重缺陷）
- **MRB 评审中 (Warning)**：`#faad14`（待审核池、审批流转中、特采待决）
- **字体栈**：优先渲染 `PingFang SC`, `Microsoft YaHei`, `Segoe UI`, `Inter`，代码与数值采用等宽字体 `JetBrains Mono`。

## 3. 核心业务组件封装规范

1. **高级多维组合筛选器 (`AdvancedFilterBar`)**：
   - 支持来源单据号、物料编码、供应商名称、检验员、时间区间的动态组合。
   - 自带记忆筛选偏好及本地缓存，车间工位快速切换免重复输入。
2. **多指标检验录入矩阵 (`MeasurementMatrixTable`)**：
   - 定量项（标称值、上限、下限）支持输入后**实时客户端极速判定**合格与否并高亮红绿色彩。
   - 快捷键支持 Enter/Tab 键在网格内极速跳格录入，支持数显量具串口自动回车灌入数据。
3. **批次全景双向追溯拓扑树 (`BatchTraceGraph`)**：
   - 基于 ECharts Tree / Graph 封装，支持正向追溯（从原材料进厂 -> 工序流转 -> 销售出库）与反向倒查（从客诉退货出库单 -> 倒查炉批号与来料卷号）。
   - 节点颜色直观映射质检合格状态，阻断批次红圈警示。
4. **MRB 状态机多级审批时间轴 (`MrbAuditTimeline`)**：
   - 动态展示技术、质量、生产多部门协同审批意见、签名留痕及最终处置流转。

### 2.2 来料检验 (IQC) 表格列规范与交互定义 (对应 WPS图片(2))

表格列名依次为：
1. **检验单号** (`orderNo`): 蓝色单号，可点击查看详情或质检工作台。
   单号规则 `{类型前缀}-{YYYYMMDD}-{4位流水号}`；来料检验沿用 `INS` 历史口径，创建时可省略、由服务端原子取号（见文档 16 §7.11）。
2. **采购入库单号** (`receiptNo` ← 库 `receipt_no`): 关联管家婆 ERP 采购入库单号（如 `RK-20260706-001`）。
   **必须取库中真实列**：历史上曾由 `'RK-' + 检验单号去前缀` 推导，属于伪造值，已随 §7.13 一并清除；库中无值时显示 `-`。
3. **入库日期** (`receiptDate`): ERP 采购入库制单日期（如 `2026-07-06`）。
4. **物料编号** (`materialCode`): 原材料编码（如 `CL-001`）。
5. **物料名称** (`materialName`): 原材料全名（如 `不锈钢棒料`）。
6. **规格型号** (`spec`): 材质规格型号（如 `Φ20mm`）。
7. **数量** (`qtyDisplay`): 采购入库实收数量及计量单位（如 `500 件`）。
8. **供应商** (`supplier`): 供应商全称（如 `宝钢`）。
9. **批次号** (`batchNo`): 进厂物料批次（如 `LOT-20260706-001`）。
10. **检验状态** (`status`): 状态徽标（`待检验` 灰、`检验中` 蓝、`已合格` 绿、`不合格` 红、`已关闭` 深灰）。
11. **检验人** (`inspectorName`): 质检员姓名，未分配或待检时显示 `-`。
12. **操作** (`actions`):
    - `待检验` 状态：【检验】、【详情】
    - `检验中` 状态：【检验】（或继续）、【详情】
    - `已合格` / `不合格` / `已关闭` 状态：【详情】、【追溯】
    - 支持打开追溯拓扑模态框与详情抽屉/模态框。

### 2.3 出货检验 (OQC) 表格列规范与交互定义 (对应 WPS图片(9) 与最新设计)

表格列名依次为：
1. **检验单号** (前端 `docNo` ← 接口 `orderNo` ← 库 `order_no`): 蓝色单号超链接（如 OQC-SH-20260706-0001），点击可查看质检详情或启动质检录入。
   单号规则 `{类型前缀}-{YYYYMMDD}-{4位流水号}`（出货检验前缀 `OQC-SH`）；创建时可省略，由服务端在事务内原子取号（见文档 16 §2.3、§7.11）。
2. **销售出库单号** (salesOrderNo / salesDispatchNo): 关联管家婆 ERP 销售出库单据编号（如 SO-20260706-01）。
3. **出库日期** (dispatchDate / orderDate): 销售出库制单日期（如 2026-07-06）。
4. **客户** (customer): 客户全称或简称（如 客户A科技、客户B制造、客户C集团、客户D工业）。
5. **订单号** (orderNo / poNo): 客户采购订单编号（如 PO-A-001），次要灰色文字样式。
6. **成品编码** (productCode / materialCode): 成品物料编号（如 CP-001），深色加粗字体。
7. **成品名称** (productName / materialName): 成品物料名称（如 六角螺栓M10、六角螺栓M12、法兰螺栓）。
8. **数量** (qty): 销售出库数量（如 5000、3000、8000、2000）。
9. **ERP状态** (rpStatus): ERP单据审批状态徽标（待审核 琥珀色、已审核 浅绿色、已拦截 浅红色）。
10. **检验状态** (status): 出货质检业务状态徽标（待检验 浅灰色、检验中 浅蓝色、已合格 浅绿色、不合格 浅红色）。
    该列是**派生列**，由库中 `status` + `judgment` 共同决定，并非单一 `status` 字段：
    待检验 ← `PENDING` / `DRAFT`；检验中 ← `INSPECTING` / `RE_INSPECTING`；
    已合格 ← `COMPLETED` / `PASSED` 且 `judgment ≠ FAILED`；
    不合格 ← `FAILED` / `IN_MRB_REVIEW`，或 `COMPLETED` / `PASSED` 且 `judgment = FAILED`。
    顶部「检验状态」下拉即按此口径提交 `inspectionState` 查询参数（见文档 16 §5.1），
    保证**筛选结果与列上显示的字样永远一致**。
11. **检验人** (inspectorName): 质检员姓名，未开始或待检验时显示 -（如 张检验、李检验、王检验）。
12. **操作** (ctions):
    - 待检验 状态：【检验】（蓝色文字链接）
    - 检验中 状态：【继续】（蓝色文字链接）
    - 已合格 / 不合格 状态：【详情】（蓝色文字链接）

底栏分页：
- 显示当前总条数 共4条；
- 分页控件：上一页 <、当前页号高亮 1（实心蓝底白字）、下一页 >。

> 列数据的数据库字段、契约、仓储映射、API 查询参数与迁移脚本口径，见
> `docs/16-出货检验OQC数据字段与接口打通设计.md`。本节的列名/列序/配色为 UI 规范；
> 行数据一律读取 `GET /api/v1/inspections?type=OQC_SH`。原型这 4 行已作为种子数据直接落库
> （`OQC-SH-20260706-0001/0002`、`OQC-SH-20260705-0008/0007`，见 §2.3 与文档 16 §6.4），
> 页面读到的前 4 行与本节逐列一致；仅在接口报错或返回空集时才回退到内置参考数组。
> 「检验人」列规范：未开始 / 待检验一律显示 `-`，其余状态显示库中姓名，姓名缺失同样以 `-` 兜底。
> 「检验单号」列规则：新单统一按上述编号规则生成；台账中若出现 `INS-YYYYMMDD-NNN` 形态，
> 属**改规则之前的历史单号**（已被 MRB 与批次追溯引用，不可改号），并非链路未打通。


### 2.4 委外检验工作台 (表面处理 / 机加工 / 热处理) 表格列规范与交互定义 (对应 WPS图片(8) 及 WPS图片(8-2)、(8-3))

#### 1. 顶部 Tab 导航规范
包含三个标准分类 Tab：
- **表面处理检验** (surface)：对应 WPS图片(8)，包含加工类型列与顶部综合检索工具栏；
- **机加工检验** (machining)：对应 WPS图片(8-2)，展示机加工专属委外/过程任务台账，无加工类型列；
- **热处理检验** (heat)：对应 WPS图片(8-3)，展示热处理专属委外/过程任务台账，无加工类型列。

#### 2. 表格列规范
- **检验单号** (docNo / orderNo): 蓝色单号超链接（如 OQC-SF-20260706-0001、OQC-MC-20260706-0001、OQC-HT-20260706-0001），点击可查看详情或启动质检录入。
- **委外加工单号** (outsourceNo / atchNo): 关联 ERP 委外工单号（如 WW-20260706-001、WW-20260706-010、WW-20260706-015）。
- **加工类型** (processType): **仅在「表面处理检验」Tab 下展示**（蓝色徽标：镀锌、镀镍、发黑、磷化等）；在「机加工检验」与「热处理检验」Tab 下不展示该列。
- **物料编码** (materialCode): 成品/半成品物料编号（如 CP-001、CP-004、CP-006），深色加粗。
- **物料名称** (materialName): 物料全称（如 六角螺栓M10、精密轴套、连接件、高强度螺栓、弹簧垫圈）。
- **数量** (qty): 检验报检数量（如 500、100、200、1000）。
- **加工商** (endor): 委外加工厂商名称（如 苏州机加工厂、昆山加工中心、上海热处理厂、无锡热处理、东莞表面处理厂）。
- **回厂日期** (eturnDate): 委外回厂登记日期（如 2026-07-06、2026-07-05）。
- **状态** (status): 业务状态徽标：
  - 待检验: 浅灰色徽标 (g-slate-100 text-slate-600)
  - 检验中: 浅蓝色徽标 (g-blue-100 text-blue-700)
  - 已合格: 浅绿色徽标 (g-emerald-100 text-emerald-700)
  - 不合格: 浅红色徽标 (g-rose-100 text-rose-700)
- **检验人** (inspector): 质检员姓名，未分配或未检验时显示 -（如 -、王检验、张检验、李检验）。
- **操作** (ctions):
  - 待检验 状态：【检验】（蓝色文字超链接）
  - 检验中 / 已合格 / 不合格 状态：【详情】（蓝色文字超链接）

#### 3. 字段与接口落地口径 (009 迁移后)
表格十列全部绑定 `inspection_orders` 真实物理列，接口统一为 `GET /api/v1/inspections`：

| 界面列 | 契约字段 | 数据库列 | 兜底口径 |
|:---|:---|:---|:---|
| 检验单号 | `orderNo` | `order_no` | 无 |
| 委外加工单号 | `outsourceNo` | `outsource_no` | 无（缺失显示 `-`；**不再回落 `batch_no`**——批次号 ≠ 委外加工单号，混用会让台账口径失真） |
| 加工类型（仅表面处理页签） | `processType` | `process_type` | 无（为空则不渲染徽标，改渲染 `-`，禁止空胶囊占位） |
| 物料编码 / 物料名称 | `materialCode` / `materialName` | `material_code` / `material_name` | 无 |
| 数量 | `sampleQty` | `sample_qty` | 无 |
| 加工商 | `vendorName` | `vendor_name` | 其次 `supplier_name`，再次 `supplier_code`；历史行由 011 迁移按供应商主数据回填名称，界面不直接展示编码 |
| 回厂日期 | `returnDate` | `return_date` | 无（缺失显示 `-`；**不再回落 `created_at`**——制单时间不是回厂时间） |
