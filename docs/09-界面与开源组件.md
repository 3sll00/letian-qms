## 2. 设计规范与企业主题定制 (Design Tokens)

系统全局采用制造行业信赖感强的科技深蓝为主色调，符合工业质检现场清晰、高对比度的视觉要求：
- **主品牌色 (Primary)**：`#2B5AED`（操作按钮、激活态、高亮指示；原型实测值，出货检验页与质检方案设计页已按此实现；早期页面残留的 `#2563EB` 为待统一口径）
- **合格成功色 (Success)**：`#52c41a`（检验合格、放行标记、流转完成）
- **不合格告警色 (Error)**：`#ff4d4f`（检验不合格、入库阻断、严重缺陷）
- **MRB 评审中 (Warning)**：`#faad14`（待审核池、审批流转中、特采待决）
- **中性色阶（原型实测，各页表格/卡片统一）**：页面底色 `#F5F7FA`、卡片底 `#FFFFFF`、卡片描边 `#F1F5F9`、表头底色 `#F5F7FA`、分隔线 `#E2E8F0` / `#F1F5F9`、正文与标题 `#1E293B`、表单标签 `#475569`、次要文字与表头文字 `#94A3B8`；
- **字体栈**：优先渲染 `PingFang SC`, `Microsoft YaHei`, `Segoe UI`, `Inter`，代码与数值采用等宽字体 `JetBrains Mono`。
- **品牌方标（侧边栏与登录页的 `乐天QMS` 标识）**：**不用图片资源**，由 CSS 画——圆角方块内居中一枚白色加粗 `L`，
  方块填充 `bg-gradient-to-br from-[#325CEE] to-[#5D64F0]`；侧边栏 `w-7 h-7 rounded-[7px] text-[15px]`
  （`apps/web/src/components/AppLayout.tsx` 品牌头）、登录页 `w-9 h-9 rounded-[9px] text-[19px]`（`apps/web/src/pages/login/index.tsx`），
  与右侧白色 `乐天QMS` 文字同排。渐变端点取自参考图实测（方块 43×44 / `L` 帽高 ≈ 17px / 左上 `#325CEE` → 右下 `#5D64F0`）；
  历史资源 `apps/web/src/assets/logo_icon.png`（38×38）是**错位裁切**（裁进了 `乐` 字与侧边栏底色，渲染成一块碎字方块），
  已从上述两处引用中摘除，**并于 2026-09-23 删除该资源文件**（见 `docs/实施进度.md` §38），**不得再接线**。
- **顶栏工具图标（通知 / 帮助）**：全站**不使用线性图标**，统一用彩色 PNG 资源——
  `apps/web/src/assets/bell_icon.png`（金色铃铛 + 红色未读圆点）与 `help_icon.png`（红粉渐变问号），
  **透明底**、`object-contain`、以 `w-5 h-5`（20px）展示在 `w-8 h-8` 圆形悬停按钮内
  （`apps/web/src/components/AppLayout.tsx` 顶栏右区，顺序：搜索框 → 通知 → 帮助 → 用户区）。
  资源生成口径：从参考图的图标区域**紧贴裁切**（铃铛含右上圆点，问号含下方圆点）后把白底转 alpha
  （`alpha = min(255, 2 × (255 − min(R,G,B)))`，颜色不变），再 3 倍 HighQualityBicubic 放大写回 PNG；
  **禁止**用文字区/错位矩形裁切出的资源顶替（历史上出现过裁到「物料编码…」文字的坏资源）。
  红色未读圆点当前**已烘焙进铃铛资源**（页面尚无后端未读数）；若日后接真实未读计数，需改为「铃铛资源不带点 + CSS 徽标」。

## 3. 核心业务组件封装规范

1. **高级多维组合筛选器 (`AdvancedFilterBar`)**：
   - 支持来源单据号、物料编码、供应商名称、检验员、时间区间的动态组合。
   - 自带记忆筛选偏好及本地缓存，车间工位快速切换免重复输入。
2. **多指标检验录入矩阵 (`MeasurementMatrixTable`)**：
   - 定量项（标称值、上限、下限）支持输入后**实时客户端极速判定**合格与否并高亮红绿色彩。
   - 快捷键支持 Enter/Tab 键在网格内极速跳格录入，支持数显量具串口自动回车灌入数据。
3. **批次全景双向追溯看板（页面 `apps/web/src/pages/traceability`）**：
   - **批次号 / 炉批号是追溯主键**；订单号、物料编码、成品名称只是**检索条件**，先出「匹配到的批次」清单，点行再以该批次为根开图（避免把同一订单下**并列**的检验环节串成一条并不存在的血缘链）。
   - 支持**正向 / 反向 / 双向**三种穿透方向，并给出**影响面**统计（下游批次 / 上游批次 / 下游关联单据 / 下游单位，恒按生产流向计算，与查询方向无关）。
   - 节点卡片配色映射节点状态，图例**必须覆盖契约枚举的全部 6 个取值**（已合格 / 已入库 / 特采 / 不合格 / 检验中 / 待检验）；`★` 标注**本次查询的根批次**；`STORED`（已入库）用青绿而非翠绿，避免被读成「已合格」。
   - **特采（`CONCESSION` / 让步接收）**节点必须同时给出 **MRB 单号**与**客户书面授权件**，任一缺失即在卡片上显式提示「缺客户授权件（不得视为已放行）」，不得静默按合格展示。
   - 订单维度分区只叫「**本订单检验环节**」，它是**并列台账**而不是血缘链路，不使用「完整」「全链路」等穷尽性表述；穷尽性血缘只由批次图承担。
   - 结果受**物料行级数据权限（PBAC）**过滤，命中拦截返回 403 并提示「权限拦截」，与「查不到数据」区分显示（fail-closed）。
   - 完整口径与逐条验收标准见 `docs/24-质量追溯看板界面评审与改造建议.md`。
4. **MRB 状态机多级审批时间轴 (`MrbAuditTimeline`)**：
   - 动态展示技术、质量、生产多部门协同审批意见、签名留痕及最终处置流转。

### 2.1 过程检验 (IPQC) 三工序总览看板页面规范与交互定义 (对应 WPS图片(4))

#### 1. 页面定位与数据来源
子页 `overview`（`apps/web/src/pages/inspections/components/IpqcViews.tsx`），页头「过程检验总览 (IPQC)」，数据取自
`GET /api/v1/inspections/ipqc-overview`，响应四组统计：`blanking` / `rolling` / `finished` / `summary`（口径见 `docs/14`）。

#### 2. 版式（页头 → 三工序卡片 → 管控总量汇总条 → 工序控制指标汇总表）
- **三工序卡片**（下料 IPQC-CT / 滚丝 IPQC-RL / 成品检 IPQC-FN）：`bg-white` + `border-slate-200` + `rounded-xl` + `shadow-sm`；
  卡内为工序名 + 工序编码胶囊 + 合格率角标 + 四格统计条（`bg-slate-50`），四格数值配色 `待检验 amber-600 / 检验中 blue-600 / 已合格 emerald-600 / 不合格 rose-600`；
- **今日过程检验管控总量汇总条**：与三工序卡片同底色口径 —— `bg-white border border-slate-200 rounded-xl p-4 shadow-sm`；
  左侧为图标徽标（`bg-emerald-50` + `text-emerald-600`）与总量，右侧为 5 项指标（待检排队 / 检验中 / 合格放行 / 不合格拦截 / 综合合格率），
  指标之间用 `bg-slate-200` 竖线分隔。**该汇总条不得使用深色渐变底**（`from-slate-900` 一类深色容器属遗留皮肤，与 §2.5.1 的「浅色主题」同一口径）；
- **汇总条数值配色**与三工序卡片同源：待检排队 `text-amber-600`、检验中 `text-blue-600`、合格放行与综合合格率 `text-emerald-600`、不合格拦截 `text-rose-600`；
- **工序控制指标汇总表**：`bg-white` + `border-slate-200` 卡片包裹表格，表头 `bg-slate-50 text-slate-600`。

#### 3. 交互与口径
- 三工序卡片底部按钮进入对应台账子页（下料 / 滚丝 / 成品检），成品检卡片额外标注「物理阻断已启用」；
- 「刷新看板」按 `GET /api/v1/inspections/ipqc-overview` 重取，失败不得清空已有看板数据；
- 浅色主题：本子页子树内不存在深色（亮度 < 140 且不透明）容器，汇总条与卡片底色一致。


### 2.2 来料检验 (IQC) 表格列规范与交互定义 (对应 WPS图片(2))

表格列名依次为：
1. **检验单号** (`orderNo`): 蓝色单号，可点击查看详情或质检工作台。
   单号规则 `{类型前缀}-{YYYYMMDD}-{4位流水号}`；来料检验沿用 `INS` 历史口径，创建时可省略、由服务端原子取号（见文档 16 §7.11）。
2. **入库单号** (`inboundNo` ← 库 `inbound_no`): 关联管家婆 ERP 采购入库单号（如 `RK-20260706-001`）。
   口径：「采购入库单号」与「入库单号」是同一业务对象，列名与字段名统一收敛为「入库单号 / `inboundNo`」
   （迁移 021 重命名物理列，详见 `docs/25-来料检验入库单号数据字段与接口打通设计.md`）。
   **必须取库中真实列**：历史上曾由 `'RK-' + 检验单号去前缀` 推导，属于伪造值，已随 §7.13 一并清除；库中无值时显示 `-`。
3. **入库日期** (`inboundDate` ← 库 `inbound_date`): ERP 采购入库制单日期（如 `2026-07-06`）。
4. **物料编号** (`materialCode`): 原材料编码（如 `MAT-304SS-05`）。
5. **物料名称** (`materialName` ← 库 `material_name`): 物料品名快照（来源管家婆 ERP `Ptype.FullName` → `materials.material_name`，如 `不锈钢线材 Φ5.0mm`）。
   **该列只承载品名，不得承载规格型号**；ERP 品名字符串自带的简短规格后缀属 ERP 侧口径，QMS 不改写主数据。
6. **规格型号** (`specification` ← 库 `specification`；契约别名 `spec` 只读派生): 物料规格型号快照
   （来源 ERP `Ptype.Standard` → `materials.spec_model`，如 `Φ5.0mm / 盘圆 / 304HC`）。
   **必须取库中真实列**：历史上该列恒为空（建单未写入），规格内容只出现在品名列；
   迁移 `023` 已按物料主数据回填（详见 `docs/26-来料检验物料名称与规格型号数据字段与接口打通设计.md`），库中无值时显示 `-`。

### 2.5 MRB 不合格品处置页表格列规范与交互定义 (对应 WPS图片(13))

#### 2. 顶部 5 项 KPI 卡
- **待评审** (`pendingCount`)：黄色时钟图标，`status = PENDING_REVIEW` 单据数；
- **评审中** (`underReviewCount`)：蓝色放大镜图标，`status = UNDER_REVIEW` 单据数；
- **已评审** (`totalReviewedCount`)：紫色单据图标，累计已有评审结论的单据数（评审中 + 已处置 + 已驳回）；
- **已处置** (`disposedCount`)：绿色对勾图标，`status = DISPOSED` 单据数；
- **本月评审率** (`monthlyReviewRate`)：粉色报表图标，本月已处置 ÷ 本月发起总数 × 100%。
> 5 项指标一律取服务端 `GET /api/v1/mrb/records` 返回值，页面不得用当页数据自行推算（分页下会失真）。

#### 3. 筛选栏
MRB单号（模糊）、来源检验单（模糊）、评审状态（下拉：全部 / 待评审 / 评审中 / 已评审，与页签同源）、处置方式（下拉：全部 / 退货 / 返工 / 特采 / 报废）、日期（`created_at` 当日区间）+【重置】【查询】。

#### 4. 状态页签
待评审 / 评审中 / 已评审 **三个** Tab，选中项下划线高亮，**默认选中「待评审」**（与 `WPS图片(13)` 一致）；
**2026-09-23 变更**：原「已处置」Tab 已**并入「已评审」**（口径见 `docs/19-MRB不合格品处置页整合设计.md` §4.1）——「已评审」= `DISPOSED + REJECTED`，本就是「已处置」的超集，故合并**只减页签、不改谓词**，单据的处置结果由「评审状态」胶囊区分（已处置 emerald / 已驳回 rose）。
跨状态检索不走页签，而是用筛选栏「评审状态」下拉的「全部」项（该下拉与页签同源 `MRB_TABS`，收敛为 全部 / 待评审 / 评审中 / 已评审）。

#### 5. 表格列规范（十列）
1. **MRB单号** (`mrbNo`)：蓝色加粗单号（如 MRB-20260706-001）；
2. **来源检验单** (`sourceOrderNo`)：灰色等宽字体（如 IQC-20260706-0002、IPQC-RL-20260706-0001、OQC-SF-20260705-0007）；
3. **物料编码** (`materialCode`)：深色加粗（如 MAT-BLT-109-M10、MAT-WSH-M10）；
4. **物料名称** (`materialName`)：物料全称（如 碳钢圆钢、法兰螺栓、六角螺栓M10）；
5. **不合格原因** (`defectDescription`)：浅红胶囊标签（如 硬度偏低、表面锈蚀、螺纹缺牙、杆部长度超差），表头用词与 `WPS图片(13)` 一致；
6. **不合格数量** (`defectQty`)：红色加粗数值（如 30、15、50、20）；
7. **检验人** (`inspectorName`)：源检验单检验人姓名，缺失显示 `-`；
8. **发现日期** (`createdAt`)：`YYYY-MM-DD`；
9. **评审状态** (`status`)：状态胶囊——待评审 amber、评审中 blue、已评审 purple、已处置 emerald、已驳回 rose；
10. **操作**：【评审】蓝色文字链接，打开右侧「评审与处置」抽屉。

#### 6. 页头操作
- **导出报表**：导出当前查询条件下的处置列表（CSV / Excel）；
- **+ 发起评审**：打开「不合格待审核池」抽屉（阶段 1 的唯一入口）。

  节点名称、授权签署角色（`roleName`，未配置回退 `roleCode`）与特采权限文案（「具有让步特采建议权」/「仅限返工/报废判定」）；
- **节点配置清单**：五列表格 —— 顺序（`nodeLevel`）/ 节点名称 / 授权签署角色 / 是否必签（`isRequired`）/ 特采审批权（`allowConcession`）。

#### 3. 交互与口径
- 浅色主题：子页容器、卡片、表格均为浅色，无深色容器残留；
- **启停**走 `POST /api/v1/review-flows/{id}/toggle-active`（**无 `/toggle` 别名**），成功后才 `alert` 并重载列表；
  失败必须让用户看到失败，**不得本地翻转后弹成功文案**；`loadFlows()` 刷新后选中项按 `id` 重挂到本次取回的新对象，
  保证左侧角标与右侧按钮文案同源；
- 节点顺序**唯一取 `nodeLevel`**，不存在 `nodeSeq` 字段；「特采审批权」默认仅终审层级为真（PRD §3.6 特采需联合双签）。

#### 4. 接口落地口径
`GET /api/v1/review-flows`（清单）、`POST /api/v1/review-flows`（整体保存，按 `(flow_code, version)` upsert 整份 `nodes`）、
`POST /api/v1/review-flows/{id}/toggle-active`（启停）。字段物理落点见 `docs/03-数据模型.md`，字段映射、断链清单与验收口径见
`docs/21-MRB不合格品处置数据字段与接口打通设计.md` §10。

### 2.6 质检方案设计（质检方案与标准）页面规范与交互定义 (对应 WPS图片(15) 与最新设计稿)

#### 1. 页面定位与数据来源
标题「质检方案设计」，副标题「根据产品或产品分类设置质检方案，同一产品可配置多种质检方案类型」。
列表读取 `GET /api/v1/plans`、KPI 读取 `GET /api/v1/plans/stats`（查询参数与响应信封见 `docs/04-API与导入规范.md` §3.7），
**页面内不得写死演示行冒充方案库**（历史实现在页面内硬编码 12 行，已删除；演示数据统一收敛到 Mock 层 `apps/web/src/mocks/data.ts` 的 `mockPlans`）。
表格 10 列与 4 张 KPI 卡的**每一个取值都能追溯到数据库列或接口派生字段**：物料名 / 分类名 / 创建人姓名由后端读时 JOIN 派生，
方案状态由后端按版本状态派生，前端不再拉取主数据做名称映射、也不再自行推导状态（字段口径见 `docs/20-质检方案设计页数据字段与接口打通设计.md`）。

#### 2. 顶部操作
- **导入方案**：白底描边按钮（`#FFFFFF` 底 + `#E2E8F0` 描边 + `plan_import_icon.png`），点击后选择 `.xlsx / .json` 文件；
- **+ 新建质检方案**：实心品牌蓝 `#2B5AED` 主按钮，打开 `CreatePlanModal`；创建成功后回到第 1 页并刷新列表与 KPI。
  弹窗内的「版本级配置」除 GB/T 2828 抽样方案外，还有**版本生效周期**（生效起始日默认当天、截止日留空 = 长期有效，
  提交前校验起始日不得晚于截止日）；提交一律落为 `DRAFT` 草稿版本（请求体里的 `status` 被服务端忽略），
  因此按钮文案是「保存为新方案草稿」、成功提示会说明「待质量主管审批后启用」，新建后该行状态为「待审批」
  （口径见 `docs/17-检验录入界面说明与质检方案匹配口径.md` §7.5.5）。
  弹窗内的「方案编号」输入框**可留空**：留空 = 由系统按 `QP-{YYYYMMDD}-{NNN}` 取号（本地当日流水、3 位左补零、每日归零），
  提交时**不发送 `planCode` 字段**（不能用空串代替"留空"），成功后提示回显服务端返回的编码（口径见 `docs/17-…` §7.5.7，TBD-11）。

#### 3. 筛选栏（四项条件全部下沉后端）
| 界面字段 | 接口参数 | 取值来源 |
| :--- | :--- | :--- |
| 方案名称 | `keyword` | 模糊匹配方案名称/方案编号 |
| 产品编码 | `materialCode` | 物料编码精确匹配 |
| 产品分类 | `categoryCode` | `GET /api/v1/master-data/categories` 分类树编码 |
| 质检类型 | `inspectionType` | 契约 `InspectionTypeEnum`（下拉为「全部」+ 各类型展示名） |

- 四项条件为**草稿态**，仅点击【查询】才提交（并回到第 1 页），保证「界面条件 == 接口条件」，前端不对返回结果做二次过滤；
- 「产品编码」框内的 `MAT-304SS-05` 是**灰色占位提示**（`placeholder`，`#94A3B8`，与设计稿中的占位文本同色），不是已填条件：
  只有用户真正输入编码后才会作为 `materialCode` 提交，避免点【查询】时用不存在的示例编码过滤、列表必然为空；
- 【重置】同时清空草稿态与已提交态；
- 输入框回车等同点击【查询】。

#### 4. 顶部 KPI 卡（四项）
全部通过 `GET /api/v1/plans/stats` 由服务端聚合返回（契约 `PlanStats`），**不受界面筛选条件与分页影响**（与 MRB 页口径一致）：
- **质检方案总数**：`total`（去重 `plan_code`）；
- **已启用**：`enabled`（存在 `ACTIVE` 版本的方案数）；
- **待审批**：`pending`（无 `ACTIVE` 版本但存在 `DRAFT` 版本的方案数）；
- **覆盖产品数**：`productCount`（`material_code <> ''` 的去重物料数，分类通用方案不计入）。

> 严禁用当页列表数据（`pageSize=100` 全量拉取）推算全局 KPI：方案数超过一页时数字必然失真。

#### 5. 表格列规范（十列）
1. **方案编号** (`planCode`)：品牌蓝超链接，点击打开方案详情弹窗；编码为服务端取号形态 `QP-{YYYYMMDD}-{NNN}`（本地当日流水、3 位左补零），人工指定的语义化编码（如 `QP-IQC-304SS`）同样原样展示；
2. **方案名称** (`planName`)：深色加粗；
3. **适用产品**：取接口派生的 `materialName`（后端按 `material_code` 联表 `materials`），缺失回退物料编码；分类通用方案（`materialCode` 为空）显示 `categoryName`，都没有才是 `-`；
4. **质检类型** (`inspectionType`)：类型徽标——来料检验 blue、过程检验 purple、委外检验 indigo、出货检验 cyan；
5. **检验类别**：取生效版本指标项的 `metricCategory` 去重后依次展示徽标——尺寸 blue、外观 amber、硬度/性能 emerald、膜厚 cyan、成分 rose、文本 indigo，无指标项时该列为空；
6. **检验项目数**：生效版本指标项条数，文案形如 `21项`；
7. **状态**：取接口派生的 `status`（契约 `PlanStatusEnum`），方案状态徽标——`已启用` emerald、`待审批` amber、`已停用` slate；
   徽标下方另按生效版本的**生效周期**补一行小字提示 `未生效` / `已过期`（周期覆盖当天或未配置则不显示，悬停 `title` 给出完整周期与原因口径）；
8. **创建人**：取生效版本的 `createdByName`（后端按 `created_by` 联表 `employees`），无生效版本时取最新版本，缺失显示 `-`；
9. **更新时间**：`updated_at`（缺失回退生效版本 `created_at`），格式 `YYYY-MM-DD HH:mm`，次要灰色；
10. **操作**（依次为）：【编辑】（蓝色文字链接，等同方案编号）＋【升级版本】（仅该方案**无草稿版本**时显示）＋【复制】（以生效版本指标项为模板 `POST /api/v1/plans` 生成一个新方案，**始终可用**；**不再拼 `{原编码}-C{时间戳}`**，`planCode` 留空交由服务端取号 `QP-{YYYYMMDD}-{NNN}` 后回显，TBD-11）＋
    **存在待审批草稿行【审批】**（含「已启用 + 新草稿」这一升版后的常态）/ 有 `ACTIVE` 版本行【停用】/ **已停用行【启用】**（`POST /api/v1/plans/versions/{versionId}/status`，body `{ action: 'ACTIVATE' | 'DEACTIVATE' }`）。
    启停成功后**重新拉取列表与 KPI**（不本地改状态），停用前弹窗二次确认；非质量主管角色调用会被后端 **403** 拦截。
    【启用】把已停用的版本行重新激活（`ACTIVATE`）：已停用行的**方案级**状态是「已停用」，但版本行本身仍可重新启用（误停用 / 重新启用历史版本的场景）。
    【审批】的目标版本是**待审批草稿**（不是当前生效版本）：升版后方案会同时存在 `ACTIVE` 与 `DRAFT`，
    点【审批】必须把**草稿**推成 `ACTIVE`（领域状态机保证旧 `ACTIVE` 自动转 `INACTIVE`），否则只是对旧版本做一次幂等启用、
    新草稿永远批不下来。目标版本选择与按钮可见性统一由 `lib/planVersionActions.ts` 提供，口径见 `docs/17` §7.5.8。
    【升级版本】以**当前生效版本**为模板 `POST /api/v1/plans/versions/{versionId}/upgrade` 生成一个新的**草稿**版本：版本号省略时由服务端按现有最大版本号升位（`v2.5 → v2.6`）、指标项与抽样参数沿用模板版本、生效周期**不继承**（默认长期有效）；
    该行已有草稿版本时按钮隐藏（避免给出一个必然 400 的按钮）；升版**不做角色门禁**（只产草稿、不改变生效状态，与「新建方案」同级，仅做 PBAC 物料权限校验），成功后同样重新拉取列表与 KPI。

> 方案状态为**服务端派生列**（前端不再推导），由版本集合决定并随列表接口一并返回：存在 `ACTIVE` 版本 → 已启用；仅存在草稿版本 → 待审批；仅剩停用版本 → 已停用。
> 版本启停已接入：页面**不本地假改状态**，一律调启停接口后重新拉取列表与 KPI；接口只认 URL 里的**版本行 UUID**、
> 按**角色**门禁（仅质量主管 / 管理员，其余 403），启用时保证同方案**单激活态**、空指标项版本拒绝启用
> （口径见 `docs/04-API与导入规范.md` §3.7 与 `docs/17-检验录入界面说明与质检方案匹配口径.md` §7.5.6）。
> 版本升版已接入 `POST /api/v1/plans/versions/{versionId}/upgrade`（TBD-14）：升版只产出一个 `DRAFT` 草稿，
> 既有版本行与生效状态原样不动 —— 方案改动因此必须走「升版 → 审批」两步，历史检验单的 `plan_snapshot` 不会被追溯改写
> （口径见 `docs/04-API与导入规范.md` §3.7 与 `docs/17-检验录入界面说明与质检方案匹配口径.md` §7.5.8）。
> 升版后的【审批】批的是**新草稿**而非当前生效版本：两者同时存在时方案级状态仍是「已启用」，若审批打到旧版本
> 只会做一次幂等启用、草稿永远批不下来（接口 200 且界面无报错，故 TypeScript 与契约校验都发现不了）。
> 目标版本选择与按钮可见性统一由 `apps/web/src/lib/planVersionActions.ts` 提供，并由
> `apps/web/scripts/verify-plan-version-actions.mjs` 回归守门。

#### 8. 与设计稿字面值的差异口径
设计稿 12 行与 KPI 读数（12 / 10 / 1 / 36）为**演示数据**，已按原型逐列落到 Mock 层
（`mockPlans` 12 条，编号 `QP-20260706-001` ~ `012`，与设计稿逐行一致，含 1 条待审批、1 条已停用）。
离线新建方案同样由 `allocateMockPlanCode()` 按 `QP-{YYYYMMDD}-{NNN}` 当日流水取号（与真实后端同口径、不重号，TBD-11）。
真实环境读数取自真实方案库，差异属预期：
- **适用产品**取物料档案名称，故为 `10.9级六角头螺栓 M10*45 (成品)` 这类完整物料名，而非设计稿的短名（如 `六角螺栓M10`）；
- **覆盖产品数**为方案覆盖的不同物料编码数，不沿用设计稿的演示值 `36`；
- 因此「共 N 条」「创建人」等列在真实环境与设计稿字面值不同，**属数据差异，非链路未打通**。
