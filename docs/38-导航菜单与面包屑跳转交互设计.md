# 38-导航菜单与面包屑跳转交互设计

需求原文（用户指令 + 截图 `codex-clipboard-c6a3f07c...png`）：

> 我想实现点击菜单栏内容可以刷新该菜单名对应的初始界面，比如我点【过程检验-下料检验】，此时我的界面内容在下料检验内，
> 我想实现点击菜单栏的【过程检验】后跳转到【过程检验】的界面；
> 并且我想实现图片上每个界面的索引可以点击跳转到对应界面。

> 一句话口径：**左侧菜单与顶部面包屑都是"入口"，不是"标签"** —— 点同一个入口 = 回到该入口的初始界面（页面重新挂载），
> 点面包屑的上一级 = 回到上一级对应的界面。

---

## 1. 结论（先给答案）

| 编号 | 事项 | 本轮处置 | 依据 |
|:---|:---|:---|:---|
| **N1** | 点击左侧菜单项（含**点击当前已选中的菜单项**）无任何反应：处于「过程检验 → 下料检验」台账内时，点【过程检验】回不到三工序总览 | **改**：`App.tsx` 新增 `navEpoch`，**每次菜单点击（同项 / 异项一律）+1** 并参与页面挂载键 `key`，页面重新挂载 → 回到该菜单的初始界面 | 本设计 §3.1 §4.1 |
| **N2** | 顶部面包屑是两块纯文本 `<span>`（`检验管理 / 过程检验(IPQC)`），点不动 | **改**：面包屑两级全部改为可点按钮 —— 分组节点 → 分组入口页；当前节点 → 本页初始界面 | 本设计 §3.2 §4.2 |
| **N3** | 各业务页内部的子视图（IPQC 三台账、权限 / 日志 Tab、主数据 Tab、录入表单）状态只存在页内 `useState`，外部无法"复位" | **不改各页签名**：统一用"换 `key` 重挂载"实现复位，避免给 8 个页面各加一套 `resetSignal` 属性 | 本设计 §3.1 §4.1 |
| **N4** | 分组名（如【检验管理】）在系统里**不是一个页面** | **口径固化**：分组节点 = 该分组**第一个菜单项**（入口页），映射见 §3.2 表格；不新增"分组首页"空壳页面 | 本设计 §3.2 |

## 2. 现状与断链

| 位置 | 现状 | 断链后果 |
|:---|:---|:---|
| `apps/web/src/components/AppLayout.tsx` 侧边菜单 | `onClick={() => onSelectKey(item.key)}` → `App` 侧 `setCurrentNav(key)` | 点击**当前已选中**菜单项时 `currentNav` 不变 → React 不重渲染 → 无反应。用户卡在「下料检验」台账内，只能点页内的【返回总览】 |
| `apps/web/src/components/AppLayout.tsx` 面包屑 | `<span>{activeGroup}</span> / <span>{activeItemLabel}</span>` | 纯文本，无点击态、无 `title`、无 `button` 语义，键盘不可达 |
| `apps/web/src/App.tsx` `renderContent()` | 各页用 `key={`${nav}-${sessionEpoch}`}`（仅登录态换键） | 同菜单重复点击不换键 → 页内子视图（`ipqcSub` 等）保持原状 |

## 3. 交互口径

### 3.1 左侧菜单点击

| 场景 | 行为 |
|:---|:---|
| 点击**其它**菜单项 | 切换到该页面，并**从初始界面进入**（与旧行为一致，仅补上"必然重挂载"的保证） |
| 点击**当前已选中**菜单项 | 该页面**重新挂载** → 回到该菜单的初始界面（如【过程检验(IPQC)】→ 三工序总览；页内录入表单 / 台账筛选 / 详情弹窗一并复位） |
| 悬停提示 | 选中项 `title` = `{菜单名}（点击返回初始界面）`；非选中项 `title` = `{菜单名}` |

> 口径理由：菜单项在业务上代表"一个工作入口"。用户从「下料检验」台账里再点【过程检验】，期望的是"我要重新进入过程检验"，
> 而不是"无事发生"。这与浏览器"点当前页签刷新"的心智模型一致。

### 3.2 顶部面包屑点击

面包屑形态：`{分组名} / {当前菜单名}`，两级都可点。

| 节点 | 点击行为 | 示例 |
|:---|:---|:---|
| 分组节点（左，常规字重） | 跳转到**本分组入口页** = 分组内第一个菜单项（换菜单 + 重挂载） | 在【过程检验(IPQC)】内点【检验管理】→ 进入【来料检验(IQC)】 |
| 当前节点（右，加粗） | **本页重新挂载** → 回到该菜单初始界面（等价于点左侧同项菜单） | 在【下料检验】台账内点【过程检验(IPQC)】→ 回到三工序总览 |

分组入口页映射（`NAV_GROUPS` 顺序即口径，改分组顺序即改入口，不再单独维护一份映射表）：

| 分组名 | 入口页（首个菜单项） |
|:---|:---|
| 质量总览 | 检验进度总览 |
| 检验管理 | 来料检验(IQC) |
| 质检方案 | 质检方案设计 |
| 不合格品处置 | MRB不合格品处置 |
| 系统管理 | 物料权限管理 |

### 3.3 不做的部分

| 项 | 结论 |
|:---|:---|
| 引入 `react-router` / URL 路由 | **不做**：本系统是 Electron + 车间内网工作台，Session 内导航，无分享链接 / 前进后退诉求；引入路由会牵动全部 8 个页面的 props 与 Mock 探针，收益不成比例 |
| 面包屑第三级（如 `检验管理 / 过程检验(IPQC) / 下料检验`） | **暂不做**：需要给各页加"向父级上报子视图"的通道（context 或回调）。当前两级已满足"点上一级回到过程检验总览"，第三级留作后续可选项（见 §6） |
| 页内子视图在面包屑上的高亮 | 同上，随第三级一并延后 |

## 4. 实现

### 4.1 `apps/web/src/App.tsx`：菜单点击 → 换键重挂载

```tsx
/** 菜单点击代数：每次点击左侧菜单（含点击当前菜单）都 +1，用于让页面重新挂载并回到初始界面 */
const [navEpoch, setNavEpoch] = useState(0);

/** 页面挂载键：登录态变化（sessionEpoch）或菜单点击（navEpoch）都会换键 → 页面重新挂载 */
function pageKey(nav: NavItemKey): string {
  return `${nav}-${sessionEpoch}-${navEpoch}`;
}

const handleSelectNav = useCallback((next: NavItemKey) => {
  setCurrentNav(next);
  // 即使是同一个 key 也要 +1：这正是"点当前菜单刷新回初始界面"的实现点
  setNavEpoch((n) => n + 1);
}, []);
```

- `renderContent()` 的**每个分支**都统一带上 `key={pageKey('<nav>')}`（此前只有 IQC / IPQC / 委外 / OQC / MRB / 权限 6 处带 key）。
- `onSelectKey` 由 `setCurrentNav` 换成 `handleSelectNav`。
- 不新增页面级 props：复位完全靠"重挂载"，各业务页保持原签名。

### 4.2 `apps/web/src/components/AppLayout.tsx`：面包屑按钮化

- 面包屑定位由 for 循环改为一次 `NAV_GROUPS.find(...)`，同时取出分组对象与当前项，并派生 `groupEntryKey = activeGroup.items[0].key`。
- 两级节点渲染为 `<button type="button">`：分组节点 `hover:text-blue-600 hover:underline`，当前节点保留 `text-slate-900 font-bold` + 同样 hover 态。
- `title`：分组节点 = `进入「{分组名}」分组入口：{入口菜单名}`；当前节点 = `点击返回「{菜单名}」初始界面`。
- 复用既有 `onSelectKey` 回调（语义已升级为"跳转并复位"，无需新增属性）。

## 5. 影响面（重挂载 = 复位清单）

| 复位内容 | 说明 |
|:---|:---|
| 页内子视图 / Tab | IPQC 三台账回到总览；权限 / 日志 Tab 回到菜单绑定页签（原「主数据 Tab」随【ERP基础档案】模块下线移除） |
| 台账筛选与分页 | 筛选条件、页码回到初始值（列表最新一页） |
| 展开的详情 / 抽屉 / 弹窗 | 全部关闭（含 MRB 发起评审、评审处置抽屉） |
| 未提交的录入表单 | **会被丢弃**，属于本次口径的预期行为（见 §6 R1） |
| 数据请求 | 重新按初始条件拉取一次（等同于一次"刷新"） |

## 6. 边界与风险

| 编号 | 事项 | 处置 |
|:---|:---|:---|
| **R1** | 录入表单填了一半，误点菜单 → 草稿丢失 | 本轮**不拦**（不做二次确认弹窗）：表单目前无本地草稿持久化，加确认弹窗需要各表单上报 dirty 状态，属独立改造项。列入遗留 |
| **R2** | 面包屑第三级（子视图）缺失 | 见 §3.3；如需，建议做法：`AppLayout` 提供 `useBreadcrumbSubLabel(label)` 轻量 context，由 IPQC / 集成两页在切换子视图时上报 |
| **R3** | 分组节点落到"第一个菜单项"是否符合业务预期 | 已在 §3.2 把映射写成表；如现场认为【检验管理】应落到别的页，只改 `NAV_GROUPS` 顺序即可 |

## 7. 验收步骤

1. 进入【过程检验(IPQC)】→ 点卡片【进入下料台账】→ 在台账内点左侧【过程检验(IPQC)】→ **页面回到三工序总览**。
2. 同上一路径，改点面包屑右侧【过程检验(IPQC)】→ **同样回到三工序总览**。
3. 在【过程检验(IPQC)】内点面包屑左侧【检验管理】→ **切到【来料检验(IQC)】**，且 IQC 列表为初始状态（无筛选、第一页）。
4. 在【系统管理 → 操作日志】内点左侧【操作日志】→ **Tab 复位**（等价于重新进入该菜单）。
5. 任意台账输入筛选词 → 点左侧当前菜单 → **筛选条件与页码清空**，列表重新加载。
6. 键盘 Tab 能聚焦到面包屑两个节点（`button` 语义），回车可跳转。
