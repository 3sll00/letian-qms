# 乐天质量管理系统 (Letian QMS) - 库存计算优化与反范式设计 (Stock Optimization & Denormalization)

> **版本**：v2.6.0  
> **设计背景**：紧固件制造现场大批量出入库节拍极快、管家婆 ERP 库存直查性能慢、批次血缘追溯层级深

---

## 1. 制造现场库存中间态快照与反范式设计

管家婆工贸版/财贸版 ERP 底层基于复杂的财务记账凭证模型，直接在 SQL Server 库上通过 `SUM(入库) - SUM(出库)` 实时计算当前在库合格品库存极为缓慢，且易因跨表大扫描引发数据库行级锁：
1. **本地库存镜像快照表 (`inventory_stock_snapshots`)**：
   - QMS 在本地 PostgreSQL 中维护轻量级反范式库存快照表，包含：
     - `part_number` (存货编码)
     - `batch_no` (质检批次号)
     - `heat_number` (炼钢炉批号)
     - `qualified_qty` (合格品可用量)
     - `locked_qty` (待检/MRB 冻结量)
     - `last_sync_time` (最新对账时间戳)
2. **增量事件与非阻塞对账**：
   - 检验合格放行时：本地原子递增 `qualified_qty`，写入 Outbox 异步推送到管家婆完工入库草稿；
   - MRB 判定报废/退货时：本地原子核减冻结库存；
   - 每晚低峰期定时拉取管家婆 ERP 财务真实账套进行差异比对与平账。

## 2. 批次血缘追溯 DAG 拓扑反范式优化

紧固件制造从“盘圆母材入厂 -> 下料冷镦 -> 搓牙滚丝 -> 热处理网带炉 -> 表面镀锌 -> 组合包装”，跨越 6 道以上工序，追溯层级很深。如果每次追溯都执行递归 CTE 查询（Recursive CTE），层级超过 10 级时响应将突破数秒：

```
原材料批次 (盘圆批次 A, 炉批号 H01)
  └─► 下料半成品批次 B
        └─► 滚丝半成品批次 C
              └─► 热处理批次 D
                    └─► 最终成品批次 E (对应客户发货箱码)
```

### 2.1 物化闭包表 (`batch_dag_closures`)
除了存储相邻两节点的直接边表 (`batch_dag_edges`) 之外，引入**传递闭包物化表 (Transitive Closure Table)**：
- 结构包含：`ancestor_batch_no` (祖先批次), `descendant_batch_no` (后代批次), `depth` (跨越层级), `heat_number` (继承炉批号)。
- 优势：
  - **正向全景追溯**：`SELECT * FROM batch_dag_closures WHERE ancestor_batch_no = 'A'`，单次索引扫描即获所有下游成品批次，时间复杂度降为 O(1)。
  - **反向客诉倒查**：客户报修成品批次 E，通过 `WHERE descendant_batch_no = 'E'` 瞬时命中最初的炼钢炉批号 H01 及母材质保书。

## 3. 强制放行关卡判定状态预物化 (Pre-calculated Gate Pass Flag)

为确保仓库在扫码发货时获得**毫秒级放行通过**反馈，系统坚决杜绝在发货瞬间动态计算“该批次是否全部工序合格”：
1. **状态预计算**：
   - 在每道质检工单完成判定或 MRB 审批通过的瞬间，领域事件处理器即自动计算并更新工单的 `is_mandatory_gate_passed = true`。
2. **极速放行校验 API**：
   - WMS 或 PDA 扫码调用 `/api/v1/inspections/gate-check` 时，SQL 仅执行最精简的索引主键查找：
     ```sql
     SELECT is_mandatory_gate_passed, release_status 
     FROM inspection_orders 
     WHERE batch_no = $1;
     ```
   - 响应时间稳定在 5ms 以内，保障车间流水线发货毫无停顿。
