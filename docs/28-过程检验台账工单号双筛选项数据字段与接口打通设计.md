# 过程检验台账「检验工单 / 生产工单」双筛选项数据字段与接口打通设计

## 1. 背景与需求

【过程检验】-【下料检验】台账的筛选栏此前只有一个合并的「工单号/单号」输入框：前端把它
接到 `GET /inspections?workOrderNo=`，而该参数在**后端仓储层是空转的**（见 §2.2）。

现场诉求是把这一个模糊框**拆成两个独立筛选**，各管各的单号：

- **【检验工单】**：QMS 检验单号（台账「检验单号」列，物理列 `order_no`）。
- **【生产工单】**：MES 生产工单号（台账「MES生产工单」列，物理列 `work_order_no`）。

两个框**各自独立生效、叠加时为 AND**（同时填写即「该检验单 + 该生产工单」的交集）。

---

## 2. 口径决策

### 2.1 筛选框 ⇄ 台账列 ⇄ 物理列对照

| 页面筛选框 | 对应台账列 | 后端查询参数 | 物理列 | 匹配方式 |
|:---|:---|:---|:---|:---|
| 【检验工单】 | 检验单号 | `orderNo` | `inspection_orders.order_no` | 模糊匹配（`ILIKE %q%`） |
| 【生产工单】 | MES生产工单 | `workOrderNo` | `inspection_orders.work_order_no` | 模糊匹配（`ILIKE %q%`，含批次号兜底，见 §2.3） |

- 两个参数**不合并、不互斥**：同时传入时由仓储层以 `AND` 组合。
- 原有 `keyword`（跨字段联合检索，命中批次/物料/单号/操作员等）、`docKeyword`（`order_no`
  OR `inbound_no`，来料检验台账「检验单号 / 入库单号」口径）**保持不变**，本页不使用它们 ——
  过程检验台账不需要 `inbound_no` 分支，用精确的 `orderNo` 才能保证「筛出来的就是列上显示的」。

### 2.2 顺带修复：`workOrderNo` 查询参数此前静默失效

`workOrderNo` 早已存在于 `InspectionQuerySchema` 与控制器下推对象中，但：

- `OrderListQuery`（仓储查询接口）**未声明** `workOrderNo` 字段；
- `listOrders()` 的 `filter()` 构建中**没有任何** `work_order_no` 条件。

控制器用对象展开（`...(query.workOrderNo !== undefined ? { workOrderNo } : {})`）传参，
展开属性不触发 TypeScript 的 excess property 检查，因此编译期无告警、运行期被直接丢弃 ——
**老的下料检验「工单号/单号」框输入任何内容都不会改变结果集**（静默无操作）。
本轮把该参数在仓储层真正落地，并补充 `orderNo`。

### 2.3 生产工单的「批次号兜底」显示口径必须与筛选一致

台账「MES生产工单」列渲染的是 `row.workOrderNo || row.batchNo || '--'`，而读侧映射
（`mapRow`）在 `work_order_no` 为空时会把 `batch_no` 填进 `workOrderNo`
（历史 MES 同步行只有批次号）。

若筛选只查 `work_order_no`，就会出现「列上明明显示 `BATCH-xxx`、输入该值却查不到」的
**筛选与显示不一致**。因此仓储层按同一口径筛选：

```sql
work_order_no ILIKE %q%
OR ( (work_order_no IS NULL OR work_order_no = '') AND batch_no ILIKE %q% )
```

### 2.4 与既有派生筛选口径的关系

本页「检验状态」筛选走 `inspectionState`（`docs/16` §5.1 的 status + judgment 派生口径），
与本轮两个单号筛选并列叠加（AND），互不影响。

## 4. 后端改造明细

### 4.1 控制器（`GET /api/v1/inspections`）

```ts
orderNo: z.string().optional(),      // 检验单号（order_no）模糊匹配
workOrderNo: z.string().optional(),  // MES 生产工单号（work_order_no）模糊匹配
```

两个参数均按「传了才下推」透传给 `listOrders()`。

### 4.2 仓储层（`KyselyInspectionOrderRepository.listOrders`）

```ts
if (query.orderNo !== undefined && query.orderNo !== '') {
  list.push(eb('orderNo', 'ilike', `%${escapeLike(query.orderNo)}%`));
}
if (query.workOrderNo !== undefined && query.workOrderNo !== '') {
  const pattern = `%${escapeLike(query.workOrderNo)}%`;
  list.push(eb.or([
    eb('workOrderNo', 'ilike', pattern),
    eb.and([
      eb.or([eb('workOrderNo', 'is', null), eb('workOrderNo', '=', '')]),
      eb('batchNo', 'ilike', pattern),
    ]),
  ]));
}
```

模糊值统一走 `escapeLike()`，避免 `%` / `_` 被当作通配符。

## 5. 前端改造明细（`IpqcViews.tsx`）

筛选栏由 1 个输入框变为 2 个（与既有「物料编码 / 检验状态」同排）：

| 标签 | 占位提示 | 状态变量 | 下发参数 |
|:---|:---|:---|:---|
| 检验工单 | 检验单号 | `filterOrderNo` | `orderNo` |
| 生产工单 | MES生产工单号 | `filterWorkOrderNo` | `workOrderNo` |

- 【重置】同时清空两个输入框（与物料编码、检验状态一并复位）。
- 输入框宽度沿用 36（`w-36`），与其余筛选项对齐。

## 7. 验收口径

1. `GET /inspections?type=IPQC_CT&orderNo=<检验单号片段>`：命中数 > 0，且返回行 `orderNo` 均含该片段。
2. `GET /inspections?type=IPQC_CT&workOrderNo=<生产工单片段>`：命中数 > 0，且返回行
   `workOrderNo ?? batchNo` 均含该片段（含批次号兜底行）。
3. 两个参数同时传入 = 两个条件的交集（AND），不是并集。
4. 不存在的单号（如 `NOPE-ZZZ`）返回 `total = 0`，而不是退化为全量。
5. 页面：下料检验 / 滚丝检验 / 成品检三页均显示【检验工单】【生产工单】两个独立输入框，
   【重置】后两框同时清空。
