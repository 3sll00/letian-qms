# 平均阻断时长指标口径

> 状态：待客户 / 质量部最终确认。本文件先锁定口径，确认后再落地到 `GetTransferKpisUseCase.averageBlockDurationHours`。

## 1. 业务含义

「平均阻断时长」衡量**下游环节从被阻断到最终放行**的平均等待时间，用于暴露传递链瓶颈（MRB 评审、返工复检、特批豁免等）。

## 2. 关键口径（三定）

### 2.1 起点：下游首次被阻断

- **起点 = 下游单据首次尝试建单 / 放行被 422 阻断的时刻**，以 `audit_logs.action = 'GATE_BLOCKED'` 的 `createdAt` 为准。
- **不是**「上游判定不合格」的时刻。上游判定不合格是阻断原因，但真正的等待是从下游实际被拦住开始计算。
- 若同一批次多次被不同下游环节阻断，按**首次**被阻断的单据算起点（取最小 `createdAt`）。

### 2.2 终点：下游获得放行

- **终点 = 下游环节最终获得放行的时刻**，以下列任一事件首次发生为准：
  - MRB 特采签发：`mrb_reviews.disposition = 'CONCESSION'` 且 `status = 'DISPOSED'` 的 `updatedAt`。
  - 返工复检合格：新的复检单 `upstreamGateCode = 'UPSTREAM_REWORK_PASSED'` 建单时刻（`inspection_orders.created_at`）。
  - 特批豁免核准并核销：`transfer_override_tickets.status = 'CONSUMED'` 的 `consumed_at`。
  - 正常放行：下游单据 `upstreamGateCode = 'UPSTREAM_PASSED'` 建单时刻。

### 2.3 MRB 评审时间是否计入

- **计入**。从下游被阻断到放行的全周期内，MRB 评审、返工复检、豁免审批等所有等待时间均属于阻断时长。
- 该指标不拆分「评审内」与「评审外」，只回答「下游到底等了多久才放行」。

## 3. 计算公式

```text
单笔阻断时长 = 终点时间 - 起点时间（毫秒）
平均阻断时长（小时）= Σ(单笔阻断时长) / 有效样本数 / 3600000
```

- 只统计**已放行**的样本；仍处于阻断中、未终判的样本不计入分子/分母。
- 若周期内没有已放行的阻断样本，指标返回 `null`，不允许回填默认值（避免假数）。

## 4. 数据源

| 字段 | 表 | 说明 |
|:---|:---|:---|
| `createdAt` | `audit_logs` | `action = 'GATE_BLOCKED'`，取该批次首次出现的时间 |
| `disposedAt` / `updatedAt` | `mrb_reviews` | MRB 终判时间 |
| `created_at` | `inspection_orders` | 返工复检单 / 正常放行单的建单时间 |
| `consumed_at` | `transfer_override_tickets` | 豁免工单核销时间 |

## 5. 待确认项

1. 起点是否可采用「上游判定不合格」作为简化口径？（当前方案采用「下游首次被阻断」。）
2. 节假日 / 非工作时间是否需要剔除？（当前方案：不剔除，按自然时间。）
3. 报废 / 退货终止的批次是否纳入统计？（当前方案：不纳入，因无「放行」终点。）
