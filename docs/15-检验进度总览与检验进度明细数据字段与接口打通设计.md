# 检验进度总览与检验进度明细数据字段与接口打通设计文档

> 遵循原则：文档优先、口径统一、真实数据库与契约一致性

## 1. 业务背景与目标

依据 PRD §3.1 及系统原型规范（WPS图片(1).png 检验进度总览看板 与 WPS图片(11).png 检验进度明细）：
- **检验进度总览**（apps/web/src/pages/dashboard/index.tsx）：展示全厂质检核心 KPI 汇总卡片、阶段分布（IQC/IPQC/OQC）、近 7 天质量趋势、Top5 缺陷排行、最新动态以及待检验任务快捷处理列表。
- **检验进度明细**（apps/web/src/pages/dashboard/history.tsx）：展示多维度检验台账明细，提供多状态、多检验人、多供应商、跨时间段、按工单号/料号/批次号的高级多次筛选，支持分页及导出。

## 2. 数据库实体与迁移脚本确认

1. inspection_orders 表已有完备的字段支撑，包括 order_no, order_type, status, material_code, material_name, batch_no, sample_qty, pass_qty, fail_qty, judgment, inspector_id, inspector_name, inspection_date, items, plan_snapshot 等。
2. 迁移脚本 001 到 007 均已按顺序执行且覆盖完备，无需额外 DDL。

## 3. 接口与契约打通

1. 检验进度总览：GET /api/v1/dashboard/overview 由 KyselyDashboardRepository.getOverview 聚合真实数据库数据。
2. 待检验任务列表：GET /api/v1/inspections?statuses=PENDING,INSPECTING,DRAFT,RE_INSPECTING
3. 检验进度明细：GET /api/v1/inspections 支持 statuses, inspectors, supplierCodes, dateFrom, dateTo 等高级组合筛选。
4. 筛选器候选项：GET /api/v1/inspections/filters 提供动态的检验人与枚举选项。

## 4. 验证结论

所有前后端字段、接口与数据库字段均已 100% 对齐并打通，单元测试、端到端集成测试及前端构建均通过。
