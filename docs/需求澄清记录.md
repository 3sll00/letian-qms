## 2. 关键业务口径澄清与统一结论 (Q&A)

### Q1：炼钢炉批号 (Heat Number) 与质检批次号 (Batch No) 的本质区别与流转关系是什么？
- **答复与定稿**：
  - **炉批号 (Heat Number)**：代表盘圆钢材在钢厂冶炼浇铸时的物理冶炼炉号，附带原始材质单（MTC）。此字段具有**全局唯一且不可篡改**属性。无论后续经过冷镦、滚丝还是热处理，所有衍生半成品与最终成品必须**强制 100% 继承最初的炉批号**。
  - **质检批次号 (Batch No)**：是车间每道工单在 QMS 内部流转的业务流水批次号（如 `LOT-20260920-001`）。
  - 在追溯看板中，必须支持以“炉批号”为锚点，倒查该炉号生产出的全部出货成品与客户去向。

### Q2：过程检验中的“不解检”（免检标记）业务逻辑是什么？
- **答复与定稿**：
  - 部分特种批量紧固件或长期高稳定工序，经质量部经理特批后可设定“免检”。
  - 免检工单在系统内免除逐项录入千分尺与硬度计实测值，系统自动标记为“免检放行”，但依然严格生成完整的工单审计档案与放行标识，确保合规可查。

### Q3：不合格品进入 MRB 待审核池后，如何与后续评审联动？
- **答复与定稿**：
  - 各检验环节（IQC/IPQC/OQC）判定不合格时，不合格条目自动汇集进入“MRB 待审核池 (`pending_mrb_items`)”。
  - 质检主管可在待审核池中进行二次甄别，支持**单条逐项发起独立 MRB 评审**，可调整紧急度与审批流，发起后工单状态变更为 `IN_MRB_REVIEW`，杜绝缺陷零件未经评审流向下一道工序。

### Q4：质检报告导出多模板如何满足不同主机厂的严苛格式要求？
- **答复与定稿**：
  - 核心报告引擎采用四段式结构解耦：**外观质量、几何尺寸、机械性能、化学成分**。
  - 系统建立 `report_templates` 模板配置表，根据工单关联的存货分类或特定客户，动态调用匹配的模板进行参数填充与 PDF/Excel 导出。

### Q5：QMS 与管家婆 ERP 的集成边界与安全性红线？
- **答复与定稿**：
  - **零侵入原则**：严禁在管家婆生产数据库中创建表、修改表结构或创建触发器。
  - **单向读取与 Outbox 下推**：从管家婆读取物料、供应商、采购订单只使用 `WITH (NOLOCK)` 只读查询。QMS 质检放行后，通过本地事务型 Outbox 队列异步推送生成管家婆入库草稿凭证，彻底杜绝死锁与数据污染。

### Q6：「检验录入」需求中的“根据物料自动匹配质检方案”与建单接口强制 `planVersionId` 的口径如何统一？
- **提出时间**：2026-09-21（开发联调阶段口径对齐）
- **问题现象**：
  - 需求（检验录入界面）要求“根据物料自动匹配质检方案，显示需要检验的指标清单”；
  - 而建单接口 `POST /api/v1/inspections` 的契约把 `planVersionId` 定为**必填**，控制器亦拒绝空值（注释写明“禁止静默降级为自动匹配”）；
  - 应用层虽已具备 `findActivePlan(物料编码, 检验类型)` 自动匹配能力，却只存在于一条**不可达**分支中，且该分支写入的 `plan_id` 为字符串 `AUTO_MATCHED`，与数据库 `inspection_orders.plan_id UUID NOT NULL` 约束冲突（必然报错）。
- **答复与定稿（两步显式匹配）**：
  1. **前端预览（读）**：新增只读接口 `GET /api/v1/plans/match?materialCode=&inspectionType=`，按“物料编码 + 检验类型 + ACTIVE 版本”匹配，返回方案版本 ID 与指标清单，供录入页渲染待检项；未命中返回 404，页面提示联系质量工程师配置方案；
  2. **建单落库（写）**：`POST /api/v1/inspections` 的 `planVersionId` 调整为**可选**——显式传入时必须真实存在（不存在仍返回 404，“禁止静默降级”原则不变）；未传入时由服务端自动匹配，匹配不到返回 **400 `inspection-plan-not-found`**，绝不用错方案、绝不猜测；
  3. **唯一真相**：两个入口共用同一仓储方法，匹配规则只有一份；方案命中后全量固化 `planSnapshot` 快照（快照即证据），并在审计日志记录 `planMatchSource`（`EXPLICIT` / `AUTO_MATERIAL`）；
  4. **后续落地（2026-09-21 已闭环）**：分类级兜底（物料无专属方案时回退到存货分类通用方案）、方案生效周期（`effectiveStartDate / effectiveEndDate`，复用 `sampling_config`）与录入页接线均已落地，对应 TBD-01 / TBD-02 / TBD-03 全部闭环；**同轮追加闭环 TBD-04**（只读回看按 `readOnly + orderId` 读本单方案快照，单项判定取工单落库值、不在前端重算）**与 TBD-05**（定性项按与领域层相同的分隔符给候选值，判定口径不放宽）；**再一轮闭环 TBD-06**（契约新增 `acceptableValues?: string[]`，方案设计侧可结构化配可选值，判定「清单优先、标准语回落」，清单不得成为放行后门）**与 TBD-07**（委外检验补「详情」只读入口、过程检验详情弹窗改读本单方案快照，并修掉 `result === 'FAIL'` 导致不合格显示成 OK 的缺陷）。新识别 TBD-08（方案设计页无版本生效周期配置入口）、TBD-09（清单不支持同义分组与说明），详见文档 §7.6 与 §7.8。
