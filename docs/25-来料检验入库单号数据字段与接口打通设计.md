# 25-来料检验（IQC）「入库单号」数据字段与接口打通设计

需求原文：【来料检验】的列「采购入库单号」即是「入库单号」，把数据字段、数据库对接字段和接口一并改造打通
（数据库字段迁移脚本、后端契约与 API 接口）。

---

## 1. 口径结论（唯一权威）

「采购入库单号」与「入库单号」是同一个业务对象（管家婆 ERP 采购入库单 `Dlyndx.Number`，`VchType=161`），
因此全系统统一收敛为 **入库单号** 一个术语，不再保留「采购入库单号」这一列名与字段名：

| 层 | 改造前 | 改造后（唯一口径） |
|:---|:---|:---|
| 台账列名（`IqcList.tsx`） | 采购入库单号 | **入库单号** |
| 契约字段（`packages/contracts`） | `receiptNo` | **`inboundNo`** |
| 领域模型（`packages/domain`） | `receiptNo` / `getReceiptNo()` | **`inboundNo` / `getInboundNo()`** |
| 数据库物理列（`inspection_orders`） | `receipt_no` | **`inbound_no`** |
| 入库日期（同组 006 字段） | `receiptDate` / `receipt_date` | **`inboundDate` / `inbound_date`** |
| 索引 | `idx_inspection_orders_receipt_no` | **`idx_inspection_orders_inbound_no`** |
| 列表查询参数（`GET /inspections`） | `receiptNo` | **`inboundNo`** |

「入库日期」的列名本身未变，但其物理列与契约字段随同组 006 字段一并改名，
避免同一组字段出现 receipt / inbound 混用的口径分叉（口径统一原则）。

---

## 2. 数据库字段改造（迁移 `021`）

新增迁移 `packages/infrastructure/src/migrations/021_rename_receipt_fields_to_inbound.ts`（已在 `runner.ts` 注册）：

| 动作 | SQL |
|:---|:---|
| 列改名 | `ALTER TABLE inspection_orders RENAME COLUMN receipt_no TO inbound_no` |
| 列改名 | `ALTER TABLE inspection_orders RENAME COLUMN receipt_date TO inbound_date` |
| 索引改名 | `ALTER INDEX idx_inspection_orders_receipt_no RENAME TO idx_inspection_orders_inbound_no` |
| 索引兜底 | `CREATE INDEX IF NOT EXISTS idx_inspection_orders_inbound_no ON inspection_orders (inbound_no)` |
| 列注释 | `COMMENT ON COLUMN inspection_orders.inbound_no IS '入库单号（ERP 采购入库单 Dlyndx.Number, VchType=161）'` |

安全边界：

1. `RENAME COLUMN` 只改列名，不重建表、不搬数据，存量值原样保留；
2. 全部动作用 `information_schema` / `pg_class` 守卫（`IF EXISTS ... AND NOT EXISTS ...`），重复执行不报错；
3. `down` 逐项改回 `receipt_no` / `receipt_date` 与旧索引名，可回滚；
4. 历史迁移 `006` 保持原样（迁移历史不可改写），全新库按 `006` -> `021` 顺序执行后即为新列名。

## 3. 后端契约改造（`packages/contracts`）

`packages/contracts/src/schemas/inspection.ts`：

| Schema | 改造 |
|:---|:---|
| `InspectionOrderSchema`（读模型） | `receiptNo` -> `inboundNo`，描述改为「入库单号 (来自 ERP 采购入库单 Dlyndx.Number)」；`receiptDate` -> `inboundDate` |
| `CreateInspectionOrderRequestSchema`（写模型） | `receiptNo` -> `inboundNo`、`receiptDate` -> `inboundDate`，描述统一为「入库单号（ERP 采购入库单号）」/「入库日期」 |

契约是 OpenAPI 文档与运行时 Zod 校验的同一信源（`openapi({ description })`），改名后
`docs/api/letian-qms-openapi.yaml` 同步更新，避免「文档字段名与运行时字段名不一致」。

## 4. 领域 / 应用 / 仓储 / API 改造

| 层 | 文件 | 改动 |
|:---|:---|:---|
| 领域 | `packages/domain/src/models/inspection-order.ts` | 私有字段 `receiptNo` / `receiptDate` 改名；构造参数、getter（`getInboundNo` / `getInboundDate`）、`toDTO` 全链路同步 |
| 应用 | `packages/application/src/use-cases/inspections/create-inspection-order.ts` | 建单时把 `cmd.inboundNo` / `cmd.inboundDate` 透传进聚合根 |
| 应用 | `packages/application/src/use-cases/traceability/get-order-chain.ts` | IQC 来源单据号取 `order.inboundNo` |
| 基础设施 | `packages/infrastructure/src/database/schema.ts` | `InspectionOrdersTable.receiptNo` / `receiptDate` 改名 |
| 基础设施 | `packages/infrastructure/src/repositories/inspection-order-repository.ts` | `save()` 的 insert 与 `onConflict doUpdateSet` 落列改名；`mapRow` 回读改名；`toReceiptDate()` -> `toInboundDate()`（异常码 `RECEIPT_DATE_INVALID` -> `INBOUND_DATE_INVALID`）；`OrderListQuery.receiptNo` -> `inboundNo`，过滤子句与 `docKeyword` / `keyword` 的 OR 分支改命中 `inbound_no` |
| 接口 | `apps/api/src/controllers/inspections.controller.ts` | `GET /inspections` 查询参数 `receiptNo` -> `inboundNo`（下推仓储）；`POST /inspections` 建单透传 `inboundNo` / `inboundDate` |

### 4.1 列表查询参数口径

`GET /api/v1/inspections` 的来料检验相关参数最终形态：

| 参数 | 命中列 | 语义 |
|:---|:---|:---|
| `inboundNo` | `inbound_no` | 入库单号模糊匹配（新增口径，替换 `receiptNo`） |
| `docKeyword` | `order_no` OR `inbound_no` | 台账筛选框「检验单号 / 入库单号」的统一检索口径 |
| `keyword` | 批次号 / 物料 / 检验单号 / 入库单号 / 工单号 / 设备 / 销售出库单号 / 客户订单号 / 客户 | 跨字段兜底检索（入库单号分支同样改命中 `inbound_no`） |

## 5. 前端接线（`apps/web/src/pages/inspections/components/IqcList.tsx`）

| 位置 | 改造 |
|:---|:---|
| 表格表头第 2 列 | 「采购入库单号」 -> 「入库单号」 |
| 行数据类型 `IqcItem` | `receiptNo` / `receiptDate` -> `inboundNo` / `inboundDate` |
| 接口行类型 `InspectionOrderRow` | 同上，读 `o.inboundNo` / `o.inboundDate` |
| 行渲染 | `{item.inboundNo}` / `{item.inboundDate}`；缺失仍显示 `-`，不得由检验单号推导 |
| 追溯抽屉 | 「ERP采购入库单号」 -> 「ERP入库单号」，取 `traceBatchItem.inboundNo` |
| 质检证书取数 | `inspectDate: item.inboundDate` |

筛选框文案（`检验单号 / 入库单号`）与后端 `docKeyword` 口径本就一致，未改动。

## 6. 演示数据同步（`seeds`）

`packages/infrastructure/src/seeds/data.ts` 新增 `SeedOrderSpec.inboundNo` / `inboundDate`，
`runner.ts` 按「显式提供才写」透传；3 条来料检验演示工单全部带上真实入库单号与入库日期：

| 检验单号 | 入库单号 | 入库日期 |
|:---|:---|:---|
| `INS-20231011-0001` | `RK-20231011-001` | 2023-10-11 |
| `INS-20231012-0001` | `RK-20231012-001` | 2023-10-12 |
| `INS-20231013-0001` | `RK-20231013-001` | 2023-10-13 |

此前 `inbound_no` 虽已通写路径，但种子数据未填值，台账该列恒为 `-`。
「读得出来」不等于「有数据」：本轮把演示数据补齐，列值才与 ERP 采购入库单号同形。
