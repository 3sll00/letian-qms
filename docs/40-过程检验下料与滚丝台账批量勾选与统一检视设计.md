## 1. 需求与结论（先给答案）

| 需求点 | 本轮处置 | 落点 |
|:---|:---|:---|
| 下料检验 / 滚丝检验台账**表左侧有勾选框** | 两页台账首列新增**行选择列**（`input[type=checkbox]`），列头为「全选本页」复选框（含 `indeterminate` 半选态） | `IpqcViews.tsx`（表头 / 数据行） |
| 支持**全选多选** | 列头复选框 = 勾选 / 取消勾选**本页全部行**；行复选框 = 逐行多选；工具栏实时显示「已勾选 N 条」并可【清空选择】 | §3.1 / §3.2 |
| 表格**右上角**增加按钮【检视】 | 台账卡片头部（表格正上方、右对齐）新增【检视】按钮，**未勾选时禁用**（`disabled` + `title` 提示） | §3.3 |
| 点【检视】后**可选合格 / 不合格** | 弹出「批量检视」对话框：已勾选条数 + `合格` / `不合格` 二选一 +【确定】/【取消】 | §3.4 |
| 合格 → 勾选的**统一合格**；不合格 → 勾选的**统一不合格** | 逐条走**终判唯一写入口** `POST /api/v1/inspections/{id}/status`（`status = judgment = PASSED / FAILED`），失败行单独回报并保留勾选便于重试 | §4 |

## 2. 现状与基线（改造前）

| 位置 | 现状 | 影响 |
|:---|:---|:---|
| `IpqcViews.tsx` 台账 | 三页（下料 / 滚丝 / 成品检）均为 **11 列**、无行选择列 | 只能逐行进【检验】弹窗录判定，一批 10～100 条单据要重复点 10～100 次 |
| 「操作」列 | 待检验 →【检验】（单行弹窗）；其余 →【详情】 | 单行录入是**全项实测值 + 综合判定**的完整流程，适合需要录数据的场合；不适合"抽检看一遍统一放行" |
| 三页台账列集口径 | `docs/29` §2（下料）/`docs/30` §2（滚丝·成品检）逐列钉死 11 列 | 新增勾选列**不得**改动这 11 列的业务列集与顺序（勾选列是界面选择器，不是业务数据列） |
| 终判写路径 | `POST /inspections/{id}/status` 自 `docs/39` 起为**终判唯一写入口**：同一事务内状态流转 → 数量 / 结论 / 终判时间 → **判不合格自动汇入不合格待审核池** → 审计留痕 | 批量检视**必须复用它**，不得新开写路径（否则入池与审计会在批量路径上再次断链） |

> 口径依据（文档最高权威）：`docs/01-PRD.md` §3.3 过程检验三工序；`docs/17` §4 检验录入；`docs/39` §2 D1 终判唯一写入口。

## 3. 交互口径

### 3.1 勾选与全选

| 元素 | 行为 | 备注 |
|:---|:---|:---|
| 表头复选框（首列） | 未全选 → **全选本页**（并入已有勾选）；已全选 → **取消本页勾选** | 半选（部分勾选）时显示 `indeterminate` 态 |
| 行复选框 | 逐行切换勾选（多选） | 与行内【检验】/【详情】/【证书】按钮互不干扰 |
| 勾选范围 | **以当前页为口径** | 翻页 / 换子页 / 执行查询 / 重置筛选一律**清空勾选**（§3.5） |
| 表头末列「操作」 | 不变（单行【检验】/【详情】+【证书】） | 批量能力**只增不减** |

### 3.2 工具栏（表格右上角）

表格卡片头部一行：左侧文案「已勾选 N 条 · 检视后统一判定」（未勾选时提示「勾选左侧复选框后可批量检视（支持全选）」），
右侧 `清空选择`（仅在有勾选时出现）+【检视】按钮。

| 状态 | 【检视】按钮 |
|:---|:---|
| 未勾选 | 禁用（灰底、`cursor-not-allowed`），`title` = 「请先勾选需要检视的记录」 |
| 已勾选 | 可用（蓝底白字），`title` = 「对已勾选的 N 条记录批量检视」 |

### 3.3 「批量检视」对话框

- 标题：`批量检视：已勾选 N 条过程检验单`，副标题写明「统一判定后逐条落库，判不合格自动汇入不合格待审核池」；
- 结论二选一（单选态高亮，默认 `合格`）：`合格`（绿）/ `不合格`（红）；
- 底部：【取消】/【确定】（提交中禁用并显示「提交中…」）；
- 关闭方式：【取消】、右上角 `×`、提交成功后自动关闭。

### 3.4 提交口径

| 场景 | 行为 |
|:---|:---|
| 全部成功 | 关闭对话框 → 台账出现绿色提示「已将勾选的 N 条过程检验单统一判定为合格 / 不合格」→ 刷新当前页数据 → 清空勾选 |
| 部分失败 | **对话框保持打开**，红字列出「已判定 X 条，Y 条失败：`单号（原因）`」，**失败行保留勾选**（成功行取消勾选）便于就地重试 |
| 单条数据未变化 | 重复判定同一状态是幂等写入（状态回流合法，审计逐条留痕） |

### 3.5 勾选清空时机（唯一口径）

1. 切换子页（下料 / 滚丝 / 成品检 → 或返回总览）；
2. 翻页（上一页 / 下一页）；
3. 点【查询】（提交筛选条件）或【重置】；
4. 批量检视成功提交后。

> 刻意**不**保留跨页勾选：勾选范围与「当前页可见行」严格一一对应，批量检视绝不会对**页面上看不见的行**下手。

### 3.6 适用页面范围

**仅**下料检验（IPQC-CT）与滚丝检验（IPQC-RL）开放勾选列与【检视】按钮；
**成品检（IPQC-FN）不开放**——成品检是 `isMandatoryGate` 入库物理阻断关卡（`docs/01` §3.3、`docs/30` §2），
保持"逐单录入实测值 + 综合判定"的关卡语义，不提供一键批量放行入口。

## 5. 口径定义（定稿）

### 5.1 数量列口径

批量检视**不新增**任何数量推导规则，与单行快速终判保持同一条口径：

- 本单有真实抽样数（`sampleQty` 为有限数值）：合格 → `passQty = sampleQty`、`failQty = 0`；不合格 → `passQty = 0`、`failQty = sampleQty`；
- 本单**没有**抽样数：**不下发**数量字段，由终判用例保留库中原值（`updateStatsAndVerdict` 只写显式传入的键）；
- 绝不用演示值顶替（**不写** `sampleQty || 32` 这类兜底），与 `docs/32` §2.2「不编造数据」同源。

### 5.2 写路径与副作用

1. **唯一写入口**：批量检视逐条调用 `POST /inspections/{id}/status`，参数 `status = judgment = PASSED | FAILED`；
2. **同事务**：每条单据各自在自己的事务里完成状态 / 数量 / 结论 / 终判时间写入、回读、入池、审计——**一单失败不影响其它单**（失败原因逐条回报给用户）；
3. **判不合格自动入池**：`FAILED` 触达 `docs/39` §4.1 的同一判定式 → 汇入不合格待审核池（幂等 upsert）；
4. **审计**：每条单据一条 `STATUS_CHANGE` 审计记录（批量操作不是"一条审计"，逐单可追溯）；
5. **PBAC**：逐条走终判用例的三维写侧校验（fail-closed），无权限的单**逐条失败**并回报，不做"整批静默跳过"。

### 5.3 勾选列不是业务列

`docs/29` §2 / `docs/30` §2 定义的**业务 11 列**与顺序**不变**；勾选列是行为选择器，
只在**下料 / 滚丝**两页出现在最左侧，不参与列对账（回归脚本读表头时先剥离该列，再断言 11 列一致）。
