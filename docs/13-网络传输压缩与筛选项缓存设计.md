# 乐天质量管理系统 (Letian QMS) - 网络传输压缩与筛选项缓存设计 (Network Compression & Filter Cache)

> **版本**：v2.6.0  
> **面向场景**：弱网工业现场快速响应、超大列表数据传输减负、万级基础主数据秒级过滤

---

## 1. 传输层全量压缩方案 (Gzip & Brotli Compression)

质检工单明细包含大量重复键名的检验指标对象、公差范围及字符描述，原生 JSON 体积容易膨胀：
1. **Fastify 压缩管道挂载**：
   - 后端集成 `@fastify/compress`，配置自适应智能压缩：
     ```typescript
     await app.register(fastifyCompress, {
       threshold: 1024, // 仅对 > 1KB 的响应体触发压缩
       encodings: ['br', 'gzip', 'deflate'],
       zlibOptions: { level: 6 }, // 兼顾 CPU 压缩开销与压缩率的最佳平衡点
     });
     ```
   - 典型质检导出包（如 500 条工单数据，原始体积约 2.4MB）经 Brotli 压缩后仅约 180KB，网络带宽消耗减少 92%，移动端与工控机加载延迟缩短至 1/5。

---

## 2. 模式驱动极速序列化 (Fast JSON Stringify Acceleration)

Node.js 原生 `JSON.stringify` 属于动态反射递归，序列化大批量实体数组时 CPU 耗时高：
1. **结合 Zod -> JSON Schema 预编译**：
   - Fastify 内建采用 `fast-json-stringify` 引擎。系统在每个 Route 的 `schema.response[200]` 中显式声明了 `@letian/contracts` 的数据结构。
2. **加速效果**：
   - 序列化器根据预定义 Schema 直接生成平铺的代码拼接函数，杜绝了运行时的类型猜测。基准测试下吞吐量（RPS）提升 2.5 倍，服务器 CPU 占用下降 40%。

---

## 3. ERP 基础主数据筛选项客户端二级缓存 (Master Data Filter Cache)

在制造 QMS 中，**供应商字典、客户档案、存货品类树、质检标准模板**属于**读极多、写极少**的基础档案：
1. **服务端 ETag / 条件请求协商**：
   - 提供专用聚合接口 `/api/v1/meta/filter-options`。
   - 服务端记录这批主数据的版本版本哈希（Hash），响应头附加 `ETag: "w/hash-v2.6.0"` 及 `Cache-Control: max-age=600, stale-while-revalidate=3600`。
   - 浏览器或 Electron 客户端发起请求时附带 `If-None-Match`，未变更时直接返回 `304 Not Modified`，0 数据传输开销。
2. **前端 TanStack Query 本地持久化**：
   - 前端将下拉筛选选项缓存于内存中（`staleTime: 30 * 60 * 1000`，即 30 分钟内免请求）。
   - 用户在各模块（IQC、IPQC、OQC、追溯、MRB）之间切换时，物料与供应商下拉选择框**瞬时秒出**，毫无白屏等待感。
