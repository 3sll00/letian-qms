## 33. 遗留 R6 / R7 收口：仓库行尾归一 + 探针运行目标自检（2026-09-22）

**1）R6：仓库范围的行尾（EOL）混行 —— 已收口**

- 实测 `git ls-files --eol`：索引（HEAD blob）里文本文件**本来就是 LF**（0 条 CRLF blob），脏的只是**工作区** ——
  75 个文本文件带 CRLF（56 混行 + 19 全 CRLF）。
- 根因：仓库**没有 `.gitattributes`**，而本机 `core.autocrlf=true` 会在比对时把 CR 归一，于是 `git status` 完全看不见这种脏；
  一旦脚本按字节读文件（`includes` / `replace`），CR 进字符串就会**静默不命中**。
  （本轮前的一次行尾归一脚本正是踩在这个盲区上：把 74 个已跟踪文本文件的行尾误抹平，最后靠 `git cat-file blob :<file>`
  按索引逐个重建才恢复 —— 反过来也证明「索引 blob = 存档形态」这条口径可靠。）
- 处置：补根 `.gitattributes`（`* text=auto eol=lf` + `png/jpg/ico/exe` 等 `binary`）→ 把工作区文本文件**整文件写回 LF** →
  新增 `pnpm verify:eol`（`scripts/testing/eol-check.cjs`，纳入 `scripts/testing/README.md` §六）。
- **不需要改本机 git 配置**：`.gitattributes` 的 `eol=lf` 优先级高于 `core.autocrlf`，对已跟踪文本文件不再起作用。
- 实测：`pnpm verify:eol` **PASS**（已跟踪文件 615 = 文本 366 + 二进制 249；索引非 LF **0**；工作区带 CRLF **0**）。
