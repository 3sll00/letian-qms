## 4. 修复说明（原 F-7 / F-8）

用户裁定（取代原 TBD-03「跨物料只提示不阻断」）：**同炉批号必须参与门禁，跨工序物料变化不能让链路静默失效。**

### 改动点

| 文件 | 改动 |
|:---|:---|
| `packages/domain/src/ports/repositories.ts` | `findChainCandidates` 新增 `crossMaterialAnchorKinds?: readonly ChainAnchorKind[]` 选项 |
| `packages/infrastructure/src/repositories/inspection-order-repository.ts` | 传入 `['HEAT']` 时，同一炉批号下的**跨物料上游单进入候选集并参与门禁**；BATCH/WORK_ORDER 锚点仍要求同物料（同批次即同一物理批，跨物料属异常合批） |
| `packages/application/src/use-cases/inspections/check-transfer-permit.ts` | 调用 `findChainCandidates` 时传入 `crossMaterialAnchorKinds: ['HEAT']`（建单门禁、看板预览、追溯看板共用同一入口，一处生效） |
| `packages/domain/src/services/transfer-gate-service.ts` | 候选新增 `crossMaterial` 标记；决策新增 `crossMaterialUpstream` 可解释性字段（界面可说明「被一张不同物料的单挡住」）；理由文案更新 |
| `packages/contracts/src/schemas/transfer.ts` | `TransferDecisionSchema` 补充 `crossMaterialUpstream`（否则 zod 默认 strip，前端拿不到该标志） |
| `decide-mrb-disposition.ts` | 无需改动：`terminateChainWriteBack` 取下游时本就不传 `materialCode`，已涵盖跨物料冻结 |

### 根因回顾（已修复）

原 `findChainCandidates` 在 `materialCode` 非空时强制 `where materialCode = 本单物料`，跨物料上游根本不进候选集，只由 `countCrossMaterialCandidates` 计数提示。紧固件工艺链物料编码天然随工序变化（盘条→毛坯→搓丝半成品→成品），导致「按炉批号传递」在最需要它的跨工序场景**静默放行**。现改为 HEAT 锚点放开物料限制，跨物料上游参与判定。
