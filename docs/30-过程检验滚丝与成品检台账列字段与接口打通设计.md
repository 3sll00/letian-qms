## 1. 背景与口径来源

【过程检验】-【滚丝检验】【成品检】两页的台账列集，按业务确认的高保真原型图收敛为 **11 列**：

- 滚丝检验：`docs/prototypes/WPS图片(6).png`
- 成品检：`docs/prototypes/WPS图片(7).png`

**口径可信性佐证**：`docs/prototypes/WPS图片(5).png`（下料检验）与业务方提供的下料检验表格截图
**逐格一致**（同一批演示数据：`IPQC-CT-20260706-0001` / `150.2 mm` / `陈操作` / `EQ-001` / `2026-07-06 08:30`），
说明 `docs/prototypes/` 这组图就是本项目列集的权威依据（映射见 `docs/09-界面与开源组件.md`）。
因此本页三张图（5/6/7）即三页台账的验收口径，`docs/01-PRD.md` §3.3 里早期那段「工单号、规格型号、
批次号、工序号…」的粗描述与图不符，本轮已同步更正。

### 1.1 三页列集差异（唯一的分叉点）

| 子页 | 检验类型 | 第 6 列起的「工序专有列」 | 检验人列 | ★ 关卡列 | 总列数 |
|:---|:---|:---|:---:|:---:|:---:|
| 下料检验 | `IPQC_CT` | 断料长度 · 操作员 · 设备 | 无 | 无 | 11 |
| 滚丝检验 | `IPQC_RL` | 操作员 · 设备 | 有 | 无 | 11 |
| 成品检 | `IPQC_FN` | 终检组 | 有 | 有（`is_mandatory_gate`） | 11 |

> 说明 1：**滚丝检验图（6）没有「螺纹规格」列**，`thread_spec` 仍落库、仍可 `?threadSpec=` 筛选，
> 并继续在详情弹窗中展示；台账列集以设计图为准，不额外增列。
> 说明 2：**下料检验图（5）没有「检验人」列**，故「检验人」只出现在滚丝 / 成品检两页（前端按 `sub` 分叉，见 §6）。
> 说明 3：**「操作员」与「检验人」是两个不同的人**（业务确认）：操作员 = 工序机台作业员（工序执行人，`operator_id` / `operator_name`），检验人 = 质检员（`inspector_id` / `inspector_name`）。两者各自独立落库、独立展示，**禁止互相推导或回填**——缺哪个列就显示 `--`。
> 说明 4：**滚丝台账最左侧另有「行选择列」**（页头全选复选框 + 每行复选框）与其右上角【检视】按钮，
> 用于勾选后统一判定「合格 / 不合格」——该列是**行为选择器**，不计入上表 11 列业务列集，
> 也**不参与**列对账（回归脚本读表头时先剥离该列）。成品检页**不开放**该列与【检视】按钮（★ 关卡页保持逐单录入）。
> 口径与实测见 `docs/40-过程检验下料与滚丝台账批量勾选与统一检视设计.md`。

## 2. 列 × 字段 × 接口对照（口径唯一）

### 2.1 滚丝检验（`IPQC_RL`）

| # | 台账列（设计图） | 接口字段 | 物理列 | 展示口径 |
|:--|:---|:---|:---|:---|
| 1 | 检验单号 | `orderNo` | `inspection_orders.order_no` | 蓝色链接（点开详情弹窗） |
| 2 | MES工单号 | `workOrderNo ?? batchNo` | `work_order_no` | `work_order_no` 为空时按 `batch_no` 兜底（读侧 `mapRow` 口径，见 `docs/28`） |
| 3 | 物料编码 | `materialCode` | `material_code` | 原样展示 |
| 4 | 物料名称 | `materialName` | `material_name` | 原样展示 |
| 5 | 数量 | `totalQty` | `total_qty` | **报检批量**（非抽检数）；缺失显示 `--`，**不用 `sampleQty` 推导** |
| 6 | 操作员 | `operatorName` | `operator_name` | 滚丝机台作业员；缺失 `--` |
| 7 | 设备 | `equipmentCode` | `equipment_code` | **设备编号**（如 `EQ-RL-02`）；缺失 `--` |
| 8 | 完成时间 | `completedAt` | `completed_at` | `YYYY-MM-DD HH:mm`；解析不出即 `--`（口径 = 该工序报工/报检登记时间） |

| 10 | 检验人 | `inspectorName` | `inspector_name` | 质检员（**≠ 第 6 列机台作业员**）；读侧缺省时按 `inspector_id` 从员工主数据补齐，都没有则 `--` |
| 11 | 操作 | —— | —— | 待检验 ->【检验】；其余 ->【详情】（证书打印在详情弹窗内） |

### 2.2 成品检（`IPQC_FN`）

| # | 台账列（设计图） | 接口字段 | 物理列 | 展示口径 |
|:--|:---|:---|:---|:---|
| 1 | 检验单号 | `orderNo` | `order_no` | 蓝色链接（点开详情弹窗） |
| 2 | ★（强制检关卡） | `isMandatoryGate` | `is_mandatory_gate` | `true` -> 琥珀色 ★；`false` -> `--`；`title` 提示「未完成检验或判定不合格严禁入库流转」 |
| 3 | MES工单号 | `workOrderNo ?? batchNo` | `work_order_no` | 同滚丝 |
| 4 | 物料编码 | `materialCode` | `material_code` | 原样展示 |
| 5 | 物料名称 | `materialName` | `material_name` | 原样展示 |
| 6 | 数量 | `totalQty` | `total_qty` | 同滚丝（缺失 `--`，不推导） |
| 7 | 终检组 | `inspectionTeam` | `inspection_team` | 缺失 `--`（**不回落**「终检一组」等默认值） |
| 8 | 完成时间 | `completedAt` | `completed_at` | 同滚丝 |
| 9 | 状态 | `status` | `status` | 同滚丝 |
| 10 | 检验人 | `inspectorName` | `inspector_name` | 同滚丝 |
| 11 | 操作 | —— | —— | 待检验 ->【检验】；**检验中 ->【继续】**（回到未完成的录入弹窗，依据图 7 第 2 行）；其余 ->【详情】 |

> `create-reinspection.ts` 把源单翻成的态）。两者都走同一入口【继续】；复检单的续录口径
> （用例层按状态机边 `RE_INSPECTING -> INSPECTING` 推进后再落数）见 `docs/17` §7.9 与本文件 §10。

## 3. 物理列与接口就绪度核查

### 3.1 已就绪（无需改造）

| 层 | 结论 |
|:---|:---|
| 物理列 | `thread_spec` / `inspection_team` / `inspector_id` / `inspector_name` / `is_mandatory_gate` / `total_qty` / `completed_at` 在 `001` / `007` 已建；`024` 已按 `IPQC_RL` / `IPQC_FN` 回填 `thread_spec` / `inspection_team` / `completed_at`（只补 NULL） |
| 契约 | `InspectionOrderSchema` 已声明 `threadSpec` / `inspectionTeam` / `inspectorName` / `isMandatoryGate` / `totalQty` / `completedAt` |
| 读侧 | 仓储 `mapRow()` 已读上述列；`inspector_name` 为空时按 `inspector_id` 查员工主数据补名 |
| 筛选接口 | `InspectionQuerySchema` 已声明 `threadSpec` / `inspectionTeam` / `operatorName` / `equipmentCode`，`listOrders()` 已在 `docs/29` 那轮落地为 `ILIKE`（`escapeLike()` 转义） |

### 3.2 断链（本轮修复）

| # | 断链 | 影响 |
|:--|:---|:---|
| ① | 前端滚丝 / 成品检仍走旧的 15 列分支（工序/关卡、规格型号、报检/抽样数、检验员…），且带 4 处**伪造兜底值**：`sampleQty \|\| 32`、`totalQty \|\| sampleQty \|\| 100`、`inspectorName \|\| '张强'`、`inspectionTeam \|\| '终检一组'` | 列集与设计图不符；空数据被假值掩盖 |
| ② | 建单写路径**从未透传** `inspectorId` / `inspectorName`：契约只声明了 `inspectorName`，控制器两条都没下推，用例命令里的 `inspectorId` / `inspectorName` 是**死字段**（从不写给聚合根） | 新建的滚丝 / 成品检单「检验人」列恒为 `--` |
| ③ | `create-reinspection` 命令同样声明了这两个死字段 | 复检轮次无法指定检验人 |
| ④ | 离线 Mock：没有 `IPQC_RL` 演示单，`IPQC_FN` 演示单缺 `inspectionTeam` / `processStep` / `completedAt` / `totalQty` | `pnpm dev:mock` 下滚丝台账为空、成品检台账多列为 `--` |

> ②③ 与 `docs/26` / `docs/29` 属同型缺陷：**契约声明了、控制器/用例没接**，输入即静默丢弃。

## 4. 数据库迁移脚本

**本轮不新增迁移**，理由：

1. 两页涉及的物理列全部已存在（`001` 的 `total_qty`、`007` 的 `thread_spec` / `inspection_team` /
   `process_step` / `completed_at` 等），无 DDL 变更；
2. 存量行的回填已由 `024_backfill_ipqc_ledger_fields.ts` 覆盖：`IPQC_RL` 补 `thread_spec`、
   `IPQC_FN` 补 `inspection_team`、IPQC 三类补 `completed_at`，且**只补 NULL**（不覆盖 MES 同步值）；
3. 「检验人」不需要回填：读侧已按 `inspector_id` 关联员工主数据补名，历史行只要有 `inspector_id` 就能显示；
   连 `inspector_id` 都没有的行，按「宁可 `--` 也不造假」口径保持为空。

## 7. 验收口径

1. 三页表头均为 **11 列**且顺序与图 5/6/7 逐列一致，旧的 15 列口径（工序/关卡、规格型号、物料编码与名称、
   报检/抽样数、检验员、报检/完成时间）**不得回流**；
2. 页面「共 N 条记录」= `GET /inspections?type=<IPQC_CT|IPQC_RL|IPQC_FN>` 的命中总数；
3. 逐行（按检验单号对齐）逐列等于接口字段：`workOrderNo ?? batchNo` / `materialCode` / `materialName` /
   `totalQty` / `operatorName` / `equipmentCode` / `inspectionTeam` / `completedAt` / `inspectorName` / `isMandatoryGate`；
4. 接口字段为空时页面必须是 `--`（重点：不得用 `sampleQty` 顶「数量」、不得用「终检一组」顶「终检组」）；
5. 操作列：待检验 -> 检验；成品检检验中 -> 继续；其余 -> 详情；**判不合格时同行追加「处置建议」**
   （返工返修 / 让步接收 / 报废，缺省返工返修）并随终判下发 `preliminaryDisposition`，回执提示「已自动发起 MRB 评审」（`docs/44`）；
6. 筛选参数落到 SQL：`?type=IPQC_RL&operatorName=` / `&equipmentCode=` / `&threadSpec=` 命中 > 0，
   `?type=IPQC_FN&inspectionTeam=` 命中 > 0，用不存在的值探测必须 `total = 0`；
7. 写路径往返：`POST /inspections` 透传的 `inspectorId` 必须落库，并由读侧补齐「检验人」姓名。

## 10. 复检轮次（`RE_INSPECTING`）续录口径（2026-09-23 补记）

**缺陷现场**：本页「状态 = 检验中」的行里，属复检轮次的单（`RE_INSPECTING`）点【继续】填完实测值后，
提交恒定红字 `ORDER_NOT_EDITABLE: 工单当前处于 [RE_INSPECTING] 状态，禁止录入或修改检验指标`
（客户实测单 `INS-20231013-0003`，`IPQC_FN` / `WO-20231013-01` / 终检一组 / 抽样 80）。

**口径与修复**：本节 §2.2 第 11 行的台账展示口径**不动**，缺口在写入口 —— `PENDING` 单有「首次录入即开检」的推进，
`RE_INSPECTING` 单没有，于是出现「界面给了入口、后端恒定拒绝」。修复落在**用例层**
（`record-measurements-and-judge.ts` / `save-inspection-draft.ts`：`PENDING` 与 `RE_INSPECTING` 一律按状态机边
