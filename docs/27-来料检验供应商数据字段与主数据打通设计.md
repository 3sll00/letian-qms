# 27-来料检验（IQC）「供应商」数据字段与供应商主数据打通设计

需求原文：【来料检验】的【供应商】帮我检查下是否跟数据库对接字段了

---

## 1. 核查结论（先给答案）

| # | 结论 | 证据 |
|:---|:---|:---|
| 1 | **字段链路是通的** | `IqcList.tsx` 读 `o.supplierName`；契约 `InspectionOrderSchema.supplierName`；仓储 `mapRow` 读 `row.supplierName`；物理列 `inspection_orders.supplier_name`（006 新增） |
| 2 | **但库里没值**：界面显示 `SUP-001` 是走了编码兜底 | 直查库：`inspection_orders` 24 行 `supplier_name` **全部为 NULL**，`supplier_code` 有值；前端 `o.supplierName \|\| o.supplierCode \|\| '-'` 因而回落到编码 |
| 3 | **筛选下拉根本没接库**（死筛选） | 【供应商】下拉是硬编码的 `宝钢 / 鞍钢 / 武钢 / 江西铜业 / 标准件厂A / 标准件厂B / 南山铝业`，与库中 `SUP-001~SUP-007` 完全对不上，选中任一项都查空 |
| 4 | **附带发现**：迁移 `021` 当时未执行 | `kysely_migration` 停在 `020`，库中列仍为 `receipt_no / receipt_date`，而代码已全链路读 `inbound_no` → 入库单号相关查询会报列不存在 |

第 2、3 条是本次要解决的主问题，第 4 条一并处理（详见 `25-来料检验入库单号数据字段与接口打通设计.md`）。

## 2. 口径结论（唯一权威）

**「供应商」列的展示值 = 供应商主数据 `suppliers.supplier_name`（厂商全称），不是内部编码。**

| 层 | 改造前 | 改造后（唯一口径） |
|:---|:---|:---|
| 台账列值 | `supplier_name` 为空时显示编码（`SUP-001`） | 展示厂商全称（`江苏大明不锈钢特钢有限公司`） |
| 展示兜底链 | `supplier_name → supplier_code` | `supplier_name 快照 → suppliers.supplier_name（按 supplier_code 回查） → supplier_code → '-'` |
| 名称权威来源 | 无（无回填） | `suppliers.supplier_name`（供应商主数据） |
| 快照列 | `inspection_orders.supplier_name` 恒空 | 建单时按主数据写入；存量行由迁移 `022` 回填 |
| 筛选下拉 | 硬编码演示厂商名 | `GET /master-data/suppliers` 实时下发 |

口径原则：

1. **快照优先**：检验单上的 `supplier_name` 是建单当时的名称快照，展示优先用它（历史可追溯）；
2. **主数据兜底**：快照为空时按 `supplier_code` 回查供应商主数据，保证展示列永远是厂商全称；
3. **不猜测**：`supplier_code` 为空或匹配不到主数据时保持 `-`，绝不编造厂商名。

## 3. 数据库字段改造（迁移 `022`）

新增 `packages/infrastructure/src/migrations/022_backfill_supplier_name_snapshot.ts`（已在 `runner.ts` 注册）：

| # | 目标 | SQL 口径 |
|:---|:---|:---|
| 1 | 台账 | `UPDATE inspection_orders o SET supplier_name = s.supplier_name FROM suppliers s WHERE o.supplier_code = s.supplier_code AND (o.supplier_name IS NULL OR btrim(o.supplier_name) = '')` |
| 2 | 不合格池 | `UPDATE pending_mrb_items p SET supplier_name = o.supplier_name FROM inspection_orders o WHERE p.source_order_id = o.id AND (p.supplier_name IS NULL OR btrim(p.supplier_name) = '') AND o.supplier_name IS NOT NULL` |

安全边界：

1. 只回填 `NULL` / 空白行，**不覆盖任何已有快照值**；
2. 名称只取自 `suppliers` 主数据，不做格式或长度猜测；
3. 编码为空或匹配不到主数据的行保持原样（如出货检验 `OQC_SH` 无供应商，其池条目仍为空）；
4. 池表语句以 `to_regclass('pending_mrb_items')` 守卫，缺表时整段为 no-op；
5. `down()` 为 no-op（数据对齐类迁移不可逆，与 `011` 一致）。

> 与种子数据构成**双保险**：`seeds/runner.ts` 的 `supplierNameOf()` 负责新写入的行，迁移 `022` 负责把已存在的历史库一次性对齐。

### 6.1 检验录入表单（`IqcRecordForm.tsx`）演示默认值清理

台账列打通后，录入侧仍有一处同源缺陷：该表单给**每一个抬头字段预置了演示值**，
其中「供货厂商」硬编码为 `鞍钢集团钢铁新材料有限公司`——与库中真实供应商无关。
变更前实测：从台账点【检验】进入录入页，材料名称恒显示演示值 `碳钢圆钢 (热轧棒料)`，
原因是取数键写错（读 `initialItem?.name`，而列表行字段名是 `materialName`），演示值因此永远命中。

| 字段 | 变更前（演示值） | 变更后 |
|:---|:---|:---|
| 供货厂商 | `鞍钢集团钢铁新材料有限公司` | 取列表行 `initialItem.supplier` / 本单 `order.supplierName`，无值则空 |
| 材料名称 | `碳钢圆钢 (热轧棒料)`（键名写错导致恒命中） | 取 `initialItem.materialName` / `order.materialName` |
| 材质牌号 | `ML40Cr` | 取 `initialItem.steelGrade`，无值则空（占位提示「按物料主数据填写」） |
| 原材料规格 | `Φ22.0 mm` | 取 `initialItem.spec` / `order.specification` |
| 原厂冶炼炉号 | `AG-20260515-B2` | 取 `initialItem.furnaceNo` / `order.furnaceHeatNo` |
| 进厂批次号 | `LOT-20260706-01` | 取 `initialItem.batchNo` / `order.batchNo` |
| 到货重量/数量 | `15.5 吨`（单位也写死为「吨」） | 由 `initialItem.qty` + `initialItem.unit` 拼接，无值则空 |
| 材料标准 | `GB/T 6478 / GB/T 699` | 空（占位提示「如 GB/T 6478」），由录入人填写 |
| 检验日期 | `2026-07-06`（固定编造日期） | 默认「今天」（录入动作真实发生日） |
| 检验员 | `张检验 (QC)` | 取列表行 `inspectorName` / 本单 `order.inspectorName` |
| 判定备注 | 一段"判定合格、准予入库"的结论文案 | 空，由录入人填写 |
| 质检组长审核 | `李审核 (QA Lead)` | 空（占位提示「待质检组长审核」） |
| 质保书客户 / 合同号 / 送检单号 / 交货状态 / 金相结论 / 外观结论 / 审核人 / 主管 | 各自预置演示文案与演示人名 | 空，交由质保书模板自身兜底 |

配套口径：

1. 列表行用 `-` 表示「无值」，回填到可编辑输入框时由 `fromList()` 还原为空串，
   **不把展示占位符当数据**带进表单；
2. 实测输入项（化学成分 / 力学 / 尺寸的实测值）属于录入内容，本轮不动。

实测：进入 `INS-20231013-0001` 的录入页，抬头为真实值（供应商 `江苏大明不锈钢特钢有限公司`、
材料名称 `不锈钢线材 Φ5.0mm`、规格 `Φ5.0mm / 盘圆 / 304HC`、批次 `B20231013-01`、数量 `50 KG`），
无来源字段均为空；截图 `scripts/logs/iqc-record-form-after-defabrication.png`。

## 9. 遗留闭环与同类观察

### 9.1 本轮已闭环

| 原遗留项 | 处置结论 |
|:---|:---|
| `IqcRecordForm.tsx` 的 `supplier` 等演示默认值 | **已闭环**：整表单演示默认值一并清理，见 §6.1 |
| `pending_mrb_items` 的 IPQC 条目无供应商 | **核实为设计如此，非缺陷**：IPQC 业务上无供应商。仓储 `mapRow` 以 `...(row.supplierName !== null ? { supplierName } : {})` 输出，条目按「无 supplierName」返回；`InitiateReviewDrawer` 亦按 `item.supplierName !== undefined` 条件渲染，界面不会出现「供应商:」空值行。如需在池中展示委外「加工商」，应另立口径 |
| 文档编号冲突（曾出现两篇 `26-`） | **已由并行任务收敛**：现为 `25 / 26 / 27 / 28` 唯一编号，本文档为 `27` |
