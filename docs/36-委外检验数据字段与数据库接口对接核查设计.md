# 36-委外检验数据字段与数据库/接口对接核查设计

需求原文：用户指令「需要你为我检查确认【委外检验】里面数据字段是否和数据库对接了字段和接口，
如果没有，则把数据库字段迁移脚本、后端契约与 API 接口一并改造打通」。

> 一句话口径：**录入页上检验员真的填了、且属于业务事实的字段，必须有「物理列 + 契约 + 接口 + 读写路径」四重落地；
> 填了却落不了的字段就是断链，而不是「界面功能」。**

## 2. 迁移 030（`packages/infrastructure/src/migrations/030_add_outsource_entry_fields.ts`）

在 `inspection_orders` 上扩展 3 个**录入页业务事实列**（与 009 的四个台账列同表、同风格）：

| 物理字段名 | 数据类型 | 可空 | 对应表单字段 | 业务说明 / 示例 |
|:---|:---|:---|:---|:---|
| `material_grade` | `VARCHAR(64)` | NULL | 材质牌号 / 强度等级 | 本单工件的材质牌号或强度等级，示例 `10.9级` / `35CrMo` / `ML40Cr` |
| `tech_standard` | `VARCHAR(255)` | NULL | 执行技术标准与工艺规范 | 本单执行的国标 / 行标 / 企标号，示例 `GB/T 3098.1-2010` / `ISO 10683` |
| `inspected_date` | `VARCHAR(32)` | NULL | 检验日期 | 检验动作真实发生日 `YYYY-MM-DD`（制造证书 Issue Date 的真实来源） |

设计要点：

1. **不新增索引**：三列都不参与台账筛选（台账无对应列），建索引只增写放大；后续若出现筛选需求再按需建。
2. **不回填历史行**：三列对历史数据都**没有可信来源**（`material_grade` 不能从物料名称猜、
   `tech_standard` 不能从方案号顶替、`inspected_date` 已知的只有建单时间）。
   迁移**刻意留 NULL**，读侧为空即不输出该键，界面留空 —— 与 `docs/32` §2.2 / `docs/34` §3 同口径。
3. **幂等**：`ADD COLUMN IF NOT EXISTS`，`down()` 用 `DROP COLUMN IF EXISTS` 还原。
4. **不动既有列语义**：`return_date` 等 009 列一律不碰。

> 回厂日期（`return_date`）**不需要新迁移** —— 009 已建列，缺的只是表单入口（§5）。

- 台账行「证书」入口（`handleOpenCert`）补齐 030 字段透传：制造证书「Specification (执行规范)」行读

`apps/web/src/mocks/{data,handlers}.ts`：委外演示行补齐 3 个字段，保证离线 Mock 与真实库口径一致。

## 6. 口径（唯一权威）

| 字段 | 读口径 | 写口径 |
|:---|:---|:---|
| `materialGrade` | 只取 `material_grade`；为 NULL/空即不输出该键，界面留空 + 占位提示 | 空串不下发（不落 NULL 覆盖既有值） |
| `techStandard` | 只取 `tech_standard`；同上。制造证书 `Specification (执行规范)` 行读它 | 同上 |
| `inspectedDate` | 优先取 `inspected_date`；**本单列为空时**才回落 `completed_at ?? created_at`（历史行无真实录入值，且制造证书 Issue Date 需要「本单已发生的登记时间」） | 表单默认「今天」（检验动作真实发生日），空串不下发 |
| `returnDate` | 只取 `return_date`；为空即不输出该键，台账渲染 `—` | 表单为空即不下发 |

> `inspectedDate` 的回落与 `docs/32` §2.2「推导值不得冒充真实字段」不冲突：回落**只在物理列为空**时发生，
> 且回落出来的值不写回数据库；一旦录入人真的填过，录入值永远优先（此前口径是「无列可落、一律推导」）。

### 7.1 回归测试扩展（`outsource-inspection-link.test.ts`）

**写路径用例**（测试文件第 2 节，本轮新增）：`POST /api/v1/inspections` 携带 `outsourceNo` / `processType` /
`returnDate` / `vendorName` / `materialGrade` / `techStandard` / `inspectedDate` 共 7 个字段建单，逐层断言：

1. `inspection_orders` 7 列与请求体逐项一致（守住「静默丢弃」回归——030 之前这三列正是被静默丢弃的）；
2. `GET /api/v1/inspections/{id}` 原样读回 7 列；
3. 委外页签按 `docKeyword=单号` 检索可见，且 7 列与库一致。

用例自建单在 `finally` 中清理（含 `pending_mrb_items` / `batch_trace_relations` 关联行），保证可重复运行。

**读路径用例**（测试文件第 1 节，本轮扩展）：`materialGrade` / `techStandard` / `inspectedDate` 必须等于物理列，
**库内为空即不得输出该键**——把「不得用 `completed_at` / `created_at` 冒充检验日期」固化成会失败的检查器
（与 §6 口径、`docs/32` §2.2 同源）。

**建单方案依赖**：用例不再依赖「某个料号恰好有专属方案」，而是**逐页签**断言——三个委外页签都必须至少有一个
可由两级匹配建单的物料，且整组用例必须覆盖**分类通用（族级）兜底**路径；代表物料由 `inspection_plans` +
`materials` 现算（不硬编码料号），任一页签缺方案会直接把用例判失败（§9 补齐的 5 份族级方案就是这条回归线的下限）。

### 9.3 为什么族级不承载硬度 / 尺寸 / 镀层厚度

- **硬度**依材料牌号（10.9 级螺栓与 65Mn 弹簧垫圈的判标值完全不同）：放进族级等于让一个件的判标值约束
  全族，属 `docs/32` §2.2 明令禁止的「用推广值冒充判标」；
- **尺寸 / 螺纹 / 粗糙度**依图纸（`MAT-SLV-45-20-30` 的外径公差与 `MAT-CON-M12` 无关）：同理；
- **镀层厚度 / 色差 / 盐雾小时数 / 扭矩系数**依表面处理工艺与客户规范（镀锌、镀镍、发黑、磷化各不相同）：
  同理，族级只写「外观均匀完整 / 附着不剥落 / 防护包装完好」这类与工艺参数无关的通用要求；
- 因此本轮只写**与件号无关的工艺级要求**；`QP-OQC-SF` 里那条 `33±3HRC`（物料级 10.9 级螺栓）**不动、也不复制** ——
  复制到族级或别的料号都等于把判标值推广到它没有依据的地方。

### 9.6 交接：物料级数值特性（主数据工作，系统不代编）

族级方案只覆盖「外观 / 防护 / 过程记录」。各件的**尺寸、螺纹、粗糙度、硬度、力学性能**须由质量工程师在
【质检方案设计】页建**物料专属方案**（命中优先级高于族级）。例：`MAT-SLV-45-20-30` 的外径 / 孔径 / 同轴度、
`MAT-WSH-SPR-M10` 的硬度与弹性、`MAT-BLT-109-M10-HT` 的回厂硬度、`MAT-BLT-88-M12` 的镀层厚度与盐雾小时数。

**仍缺方案的一行（不是本轮遗漏，是判标归属问题）**：表面处理页签的 `OQC-SF-20231013-0001`
（`MAT-35CRMO-08` 合金圆钢，`process_type = 热处理`）匹配不到方案。原材料热处理的核心判标是
**硬度 / 金相组织**，依材料牌号而变（35CrMo 与 10B21 完全不同），属 §9.3 的物料级类别 —— 族级不得承载，
否则就是又一次「用推广值冒充判标」。该行需由质量工程师建 `MAT-35CRMO-08` 的**物料专属方案**；
同时建议业务确认该历史行的工艺归类（登记在表面处理页签、工艺类型却是热处理）。
