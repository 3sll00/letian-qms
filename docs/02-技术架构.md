# 乐天质量管理系统 (Letian QMS) - 系统技术架构设计与规范说明书

> **版本**：v2.6.0 (高度可扩展增强版)  
> **设计原则**：严格遵循 DDD 领域驱动设计、六边形分层架构（Ports & Adapters）、Contract-First（契约先行）、可插拔适配器模式（Pluggable Adapters）、Outbox Sink 异步解耦、PostgreSQL 14+ 事务并发防重与 Append-Only 审计追踪。

## 2. 核心领域聚合与状态机引擎 (Domain)

### 2.1 质检方案聚合根 (InspectionPlan) 与分类批量继承
- **聚合根组成**：
  - `InspectionPlan`：主元数据（方案编码、方案名称、存货分类编码/物料编码、质检类型：IQC/IPQC/OQC/委外、有效周期：`valid_from` / `valid_to`）；
  - `InspectionPlanVersion`：版本实体（版本号 v1.0.0、状态：`DRAFT` / `ACTIVE` / `INACTIVE`、生效时间、AQL 抽样规则）；
  - `InspectionPlanItem`：指标明细（六大分类：外观、尺寸、机械性能、化学成分、硬度、膜厚；测量工具、基准值、公差上下限、单位）。
- **分类级方案批量继承机制**：
  - 领域服务 `PlanInheritanceDomainService`：当物料未定义专属特有方案时，系统自动向上寻址所属存货分类的生效方案版本；
  - 批量应用机制：支持指定存货分类并一键批量挂载至该分类下的全部在库物料。

### 2.2 不合格品待审核池与 MRB 两阶段流转状态机
- **状态流转图与关键生命周期**：
```text
[PENDING] 待检
    │
    ▼ (质检员开始录入)
[INSPECTING] 检验中 ──(暂存草稿)──► [DRAFT] 草稿
    │                                  │
    │ ◄───────(重新打开编辑)───────────┘
    │ (过程检验中支持抽检标记为“不解检”)
    ▼ (实测值全部录入并判定)
┌───┴───────────────────────────────────────┐
│                                           │
▼ (全部指标项合格)                            ▼ (存在超标项)
[PASSED] 合格                                [FAILED] 不合格
│                                           │
│ (成品检/出货放行校验通过)                    ▼ (自动汇聚)
▼                                     [PENDING_REVIEW] 不合格待审核池
[COMPLETED] 已结单                            │
                                            ▼ (主管逐条核实，人工点击“发起评审”)
                                      [IN_MRB_REVIEW] MRB 流程审批中
                                            │
                                            ├──► [RETURN] 退货 ──────────┐
                                            ├──► [SCRAP] 报废 ───────────┼─► [COMPLETED] 已结单
                                            ├──► [CONCESSION] 让步接收 ──┘   (质量档案归档)
                                            │    (需技术与客户联合签核)
                                            │
                                            └──► [REWORK] 返工/返修
                                                 │
                                                 ▼ (状态机回边)
                                            [RE_INSPECTING] 触发复检工单
                                                 │
                                                 ▼ (系统自动流向)
                                            [PENDING] (生成第 N+1 轮次检验单，关联原工单)
```

## 3. 高可扩展架构模式与六边形端口抽象 (Ports & Adapters)

为了确保平台在面对未来不同厂区、不同 ERP/MES/WMS 系统及外部委外方更迭时具备**极高可扩展性**，系统采用“端口-适配器-插件化引擎”的三层解耦架构：

```text
               ┌────────────────────────────────────────────────────────┐
               │              Letian QMS Core Application              │
               │  (Inspection / Plan / MRB / Traceability / Reporting)  │
               └────────────────────────────────────────────────────────┘
                                           │
                    ┌──────────────────────┼──────────────────────┐
                    ▼                      ▼                      ▼
             [ IErpPort ]           [ IOutsourcePort ]     [ ISalesPort ]
                    │                      │                      │
        ┌───────────┴───────────┐          │                      │
        ▼                       ▼          ▼                      ▼
 [GuanjiaPoSqlServer]     [RestApiErp]  [OutsourceDb13]    [SalesDbDirect]
 (管家婆直连选单下推)      (未来标准API)  (13张表分类分流)    (只读读取发货单)
                                                                  │
                                                        [ Outbox Event Bus ]
                                                                  │
                                                       ┌──────────┴──────────┐
                                                       ▼                     ▼
                                                [SalesSyncSink]        [FutureSink...]
                                              (可插拔回写消费者)
```

### 3.1 ERP 集成端口抽象 (IErpPort)
```typescript
export interface IErpPort {
  // 1. 基础档案只读同步
  fetchSuppliers(since?: Date): Promise<ExternalSupplierDTO[]>;
  fetchCustomers(since?: Date): Promise<ExternalCustomerDTO[]>;
  fetchMaterials(since?: Date): Promise<ExternalMaterialDTO[]>;
  fetchCategories(): Promise<ExternalCategoryDTO[]>;
  fetchWorkshops(): Promise<ExternalWorkshopDTO[]>;
  fetchEmployees(): Promise<ExternalEmployeeDTO[]>;

  // 2. 来料送检单读取
  fetchPendingInspectionOrders(filter: InspectionOrderFilter): Promise<ExternalInspectionNoticeDTO[]>;

  // 3. 检验单选单下推回写 (管家婆原生链路)
  createPurchaseInspectionBill(context: PurchaseInspectionContext): Promise<ErpBillResultDTO>;
}
```
- **管家婆财贸版专用适配器 (`GuanjiaPoSqlServerAdapter`)**：
  - 基于 `mssql` 连接池直连 SQL Server 生产只读视图与中间事务表；
  - 读取采购送检单（`fetchPendingInspectionOrders`）；
  - 检验合格结单时，调用管家婆单据选单下推存储过程/事务逻辑，生成关联原采购送检单的“采购检验单”，保留上下游键值关系。

### 3.2 委外 13 张表数据挂载与分类分流回写端口 (IOutsourcePort)
- 委外数据来源于外部 13 张表，涵盖七大工艺分类（热处理、发黑、镀锌、镀镍、磷化、达克罗、机加工）：
```typescript
export interface IOutsourcePort {
  // 读取外部13张表外协待检批次并解析挂载元数据
  fetchSubcontractOrders(category: SubcontractCategory): Promise<SubcontractBatchDTO[]>;

  // 依据数据分类分流落位回写检验结果
  dispatchInspectionResult(result: OutsourceInspectionResultDTO): Promise<OutsourceWritebackResult>;
}
```
- **回写分流规则引擎 (`OutsourceMappingRuleEngine`)**：
  - 针对热处理、镀锌等不同分类，配置目标表名称、字段映射与扫码落位规则；
  - 业务代码通过 `IOutsourcePort` 交互，完全与底层 13 张表的物理名解耦。

### 3.3 卖系统可插拔异步回写通道 (ISalesPort & Outbox Sink)
- **只读读取**：`ISalesPort` 提供读取销售订单与发货单数据的标准化查询能力；
- **回写解耦设计 (Transactional Outbox)**：
  - QMS 内部结单时，本地事务中将 `INSPECTION_COMPLETED` 领域事件持久化写入 `outbox_events` 表；
  - **一期架构**：仅本地流转，回写 Worker 处于静默或 Mock 状态；
  - **二期无缝挂载**：只需编写 `SalesSystemSinkWorker` 订阅事件，通过卖系统二期提供的写入方式回写合格数量，**核心业务事务与领域层代码 0 改动**。

## 4. 炉批号智能溯源与留痕防伪规范

### 4.1 出货检验炉批号两级追溯算法
当出货检验单输入炉批号（`heat_no`）时，Application 层编排服务执行以下溯源时序：
```text
1. 查询委外热处理检验表：
   SELECT * FROM inspection_orders o
   JOIN inspection_order_items i ON o.id = i.order_id
   WHERE o.inspection_type = 'SUBCONTRACT' 
     AND o.subcontract_category = 'HEAT_TREATMENT'
     AND o.heat_no = :heatNo 
     AND o.status = 'COMPLETED'
   ORDER BY o.completed_at DESC LIMIT 1;

2. 若命中：
   提取机械性能指标 (抗拉强度、硬度、屈服强度等)，构造继承快照 (inherited_snapshot)；

3. 若未命中，回退查询来料检验表：
   SELECT * FROM inspection_orders o
   JOIN inspection_order_items i ON o.id = i.order_id
   WHERE o.inspection_type = 'INCOMING'
     AND o.heat_no = :heatNo 
     AND o.status = 'COMPLETED'
   ORDER BY o.completed_at DESC LIMIT 1;

4. 若命中：
   提取原材料化学成分 (C, Si, Mn, P, S...) 及基础力学数据，构造继承快照；

5. 若均未命中：
   返回空继承快照，由质检员手工现场输入。
```

### 4.2 质检员手工编辑与防伪审计
```sql
-- 检验单明细表中增加继承留痕字段
ALTER TABLE inspection_order_items ADD COLUMN inherited_value VARCHAR(128); -- 自动带出的历史值快照
ALTER TABLE inspection_order_items ADD COLUMN is_manually_modified BOOLEAN NOT NULL DEFAULT FALSE; -- 是否被人为修改
ALTER TABLE inspection_order_items ADD COLUMN modification_reason TEXT; -- 修改原因说明
```
- 当质检员修改自动带出的历史值时，系统强制要求填入 `modification_reason`；
- 修改记录同步以 `INSPECTION_ITEM_OVERRIDDEN` 动作写入行级防篡改的 `system_audit_logs` 表，杜绝验厂飞检中的作弊风险。

## 5. 多模板质检报告打印子系统架构

### 5.1 四段式打印模型与模板契约
报告数据模型统一解耦为四段式通用结构：
```typescript
export interface QualityReportModel {
  meta: {
    reportNo: string;
    inspectionDate: string;
    productCode: string;
    productName: string;
    batchNo: string;
    heatNo?: string;
    customerName?: string;
    inspectorName: string;
    conclusion: 'PASSED' | 'FAILED' | 'CONCESSION';
  };
  sections: {
    appearance: InspectionReportSectionDTO; // 1. 外观检验段
    dimension: InspectionReportSectionDTO;  // 2. 尺寸检验段
    mechanical: InspectionReportSectionDTO; // 3. 机械性能段
    chemical: InspectionReportSectionDTO;   // 4. 化学成分段 (元素百分比矩阵)
  };
}
```

### 5.2 多模板引擎与导出中心
- **模板仓储模型 (`report_templates`)**：
  - 支持系统内置通用模板（`TEMPLATE_STANDARD`）、委外专属模板（`TEMPLATE_SUBCONTRACT`）以及客户客制化模板（`TEMPLATE_CUSTOM_xxx`）；
  - 模板采用基于纯数据驱动的 React-PDF 组件或 HTML/Print 模板渲染；
- **导出能力支持**：
  1. **前端直接打印**：列表页点击【打印质检报告】，选择模板后，调起打印预览窗口，支持四段合并打印或按段分页独立打印；
  2. **服务端 PDF 导出**：基于 `@react-pdf/renderer` 矢量渲染高保真 PDF 供客户验厂归档；
  3. **Excel 台账导出**：基于 `exceljs` 流式导出包含四段指标的台账明细。

## 6. PC 端通用高级组合筛选器架构 (Filter Builder)

为了满足类似管家婆的操作习惯，打造高度可扩展的查询组件：
- **Contracts 层标准化 DSL (Query DSL)**：
```typescript
export interface FilterCriterion {
  field: string;
  operator: 'EQ' | 'IN' | 'LIKE' | 'BETWEEN' | 'GTE' | 'LTE';
  values: any[];
}

export interface AdvancedQueryRequest {
  filters: FilterCriterion[];
  page: number;
  pageSize: number;
  sortBy?: string;
  sortOrder?: 'ASC' | 'DESC';
}
```
- **前端通用组件**：封装 `LetianFilterBuilder`，支持同一字段多选（如多选供应商、多选物料分类），并提供“保存常用筛选方案”功能（保存在 LocalStorage 或用户偏好表中）；
- **后端安全翻译器**：在 Infrastructure 层编写 `KyselyFilterTranslator`，白名单校验字段名，严禁任何 SQL 注入。

## 8. 高度可扩展性设计自查与落地保证

| 扩展性维度 | 现有局限 | v2.6.0 架构解耦落点 | 收益与未来演进能力 |
|---|---|---|---|
| **ERP 系统集成** | 原假设有 REST API，现实为管家婆无接口 | 抽象 `IErpPort`，实现 `GuanjiaPoSqlServerAdapter`（支持选单下推） | 未来接入金蝶/用友/SAP 或官方开放 API 时，仅需新增适配器，领域层 0 修改 |
