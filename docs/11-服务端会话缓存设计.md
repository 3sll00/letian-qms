# 乐天质量管理系统 (Letian QMS) - 服务端会话缓存设计 (Server-Side Session & Cache Design)

> **版本**：v2.6.0  
> **服务框架**：Fastify 4.x / Node.js 20 LTS  
> **设计目标**：无状态水平扩展、极速权限鉴权、百万级物料权限瞬时匹配

---

## 1. 无状态会话与安全令牌管理 (JWT Session Architecture)

为支持工厂集群负载均衡与服务零停机重启，系统采用基于 JWT (JSON Web Token) 的全无状态鉴权：
1. **的双令牌机制 (Dual-Token Pattern)**：
   - **Access Token**：有效期 2 小时，载荷中精简包含 `userId`, `userCode`, `role`, `orgId`。
   - **Refresh Token**：有效期 7 天，加密存储于客户端 HttpOnly 安全 Cookie 或安全存储中，用于无感换发新令牌。
2. **黑名单与即时注销**：
   - 当用户被管理员禁用或主动登出时，将其 Token JTI 写入内存高频 LRU 缓存并设置对应剩余存活时间 (TTL)，Fastify 鉴权中间件在解析时若命中黑名单则直接返回 `401 Unauthorized`。

## 2. PBAC 物料三维数据权限多级缓存 (Policy-Based Access Control Cache)

乐天制造业业务具有极度细化的数据隔离要求：不同质检员只能查看和操作其被授权的“特定存货分类”与“特定车间工序”的单据。每次列表检索如果都在 SQL 中拼接复杂的权限连接，会造成严重的数据库 CPU 尖刺：

```
┌────────────────────────────────────────────────────────┐
│               Fastify preHandler 鉴权钩子              │
└───────────┬────────────────────────────────────────────┘
            │ 1. 提取 Header 中的 JWT 获得 userId
            ▼
┌────────────────────────────────────────────────────────┐
│            内存本地 LRU 缓存 (PBAC Cache Store)        │
│          Key: `pbac:perms:${userId}` (TTL: 15分钟)      │
└───────────┬────────────────────────────────────────────┘
     命中    │              │ 未命中
    ┌───────┘              ▼
    │           ┌────────────────────────────────────────┐
    │           │ Kysely 查询 inventory_material_perms   │
    │           │ 回写本地 LRU 缓存                      │
    │           └───────────────────┬────────────────────┘
    ▼                               ▼
┌────────────────────────────────────────────────────────┐
│   动态生成 SQL 数据权限过滤条件 (WHERE ... IN ...)     │
└────────────────────────────────────────────────────────┘
```

1. **三维权限结构预编译**：
   - 权限规则预先编译为快速集合结构：
     - `allowedCategories: Set<string>`（允许查看的存货分类编码）
     - `allowedStages: Set<InspectionStage>`（允许操作的质检阶段）
     - `disallowedPartNumbers: Set<string>`（特例黑名单物料）
2. **主动失效与事件驱动联动**：
   - 当管理员在“系统管理 - 权限配置”界面更新了某个角色或用户的物料权限时，通过进程内事件总线或 Outbox 触发 `invalidatePbacCache(userId)`，强制下次请求重新加载最新规则，保障安全性。

## 3. Fastify 请求生命周期短驻缓存 (Request-Scoped Caching)

在高并发工单批量更新与状态机校验时，多次嵌套领域用例可能重复查询当前操作者的基本档案或系统全局质检配置：
- 挂载 `fastify-request-context`，在单次 HTTP 请求的生命周期内共享上下文查询结果。
- 单次请求执行完毕后随上下文自动回收，既彻底消除了同请求内的重复 SQL 执行，又不会产生跨请求的脏数据污染。
